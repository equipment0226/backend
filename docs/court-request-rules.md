# 사건에 맞는 서류 선정과 재요청

필요서류는 개인회생이라는 사건 종류만으로 정하지 않습니다. 관할 법원, 현재 직업과 소득, 보유 재산, 금융기관과 계좌, 채무·과거 절차 이력, 확인할 기간을 함께 보고 요청 범위를 정합니다. 고객에게는 준비할 서류와 발급 방법을 안내하고, 담당자에게는 그 서류가 필요한 이유와 적용 근거를 남깁니다.

이 기능은 상세 상담을 마친 사건에서 사용합니다. 상담 신청 단계에서 불명확한 내용을 사실로 확정해 서류를 요청하지 않습니다.

## 소득과 재산에 따라 요청이 달라집니다

급여소득만 확인된 사건에는 급여와 재직을 확인하는 자료를 중심으로 준비합니다. 현재 사업·영업·프리랜서 소득이 확인되면 사업자등록, 매출·경비·세무자료를 검토하고, 급여와 사업을 병행하면 두 소득을 구분합니다. 소득금액증명처럼 급여소득자에게도 쓰이는 자료는 사업자 전용 자료와 다르게 취급합니다.

“사업소득이 없다”는 진술, 근무처의 사업자등록번호, 빈 서식의 제목만으로 고객을 사업자로 분류하지 않습니다. “무직이 아니다”라는 문장을 무직의 근거로 사용하지도 않습니다. 현재 소득유형이 분명하지 않으면 상세 상담에서 확인할 항목으로 남깁니다.

재산과 채무 관련 자료는 확인된 계좌·채권자·보험·주거 등의 범위에 맞춰 나눕니다. 원문에 없다는 이유만으로 무재산이나 채무 없음으로 확정하지 않으며, 과거 자동 요청에 사업자 서류가 있었다는 사실도 현재 사업소득의 근거로 사용하지 않습니다.

## 법원 기준과 사건별 명령을 구분합니다

요청에는 법정 기본자료, 대체 가능한 자료, 조건에 따라 필요한 자료, 추가명령에 대비한 준비자료를 구분해 표시합니다. 대체자료를 모두 필수 제출서류로 중복 요청하거나 추가로 요구될 수 있는 자료를 이미 내려진 명령처럼 취급하지 않습니다.

현재 등록된 법원별 기준은 다음 범위입니다. 공개 원문에서 확인한 항목이며, 해당 법원의 모든 재판부·사건에 적용되는 요구를 확보했다는 의미는 아닙니다.

| 관할 | 등록된 근거 | 구분해 적용하는 대표 범위 |
| --- | --- | --- |
| 서울회생법원 | 실무준칙 제402호 | 급여증빙 대체 계좌내역 6개월, 사업 수입상황보고서 1년, 추가명령 가능한 예금거래 1년을 목적별로 구분 |
| 수원회생법원 | 실무준칙 제402호 | 급여 대체자료, 기본자료와 추가자료의 기간을 구분 |
| 부산회생법원 | 2026년 7월 1일 시행 자료제출목록 | 전체 은행거래 1년과 급여입금 2년, 사업 세무자료 3년, 지방세 자료 5년 및 상세증명·표시 옵션을 구분 |
| 광주회생법원 | 실무준칙 제402호 | 급여증빙 대체 계좌내역 6개월, 수입상황보고서 1년, 추가명령 가능한 예금거래 1년을 구분 |
| 그 밖의 등록 관할 | 세부 기준 미확인 | 확보된 공통 기준과 명시된 사건별 범위만 사용하고 추가 확인 필요 표시 |

예를 들어 급여증빙을 대신하기 위한 6개월 계좌내역 기준을 모든 은행계좌의 공통 요청기간으로 확대하지 않습니다. 부산의 전체 은행거래와 급여입금 자료도 확인 목적과 기간이 다르며, 등록된 대체자료 조건을 함께 적용합니다.

개별 사건에 보정명령이 내려오면 그 원문과 요청 범위를 별도로 연결해야 합니다. 담당자의 수동 요청과 개별 법원 명령은 일반 자동 요청의 정리 대상에 넣지 않습니다.

## 같은 서류도 기관·계좌·기간별로 관리합니다

은행이 두 곳이거나 같은 은행에 여러 계좌가 있으면 각각의 요청을 구분합니다. 같은 종류라도 기간, 목적, 발급 옵션이 다르면 별도 범위로 관리합니다. 요청 제목에는 계좌번호 끝자리만 사용하고 전체 계좌번호를 제목에 노출하지 않습니다.

고객에게는 서류명, 필요한 기간, 상태, 기한과 발급 안내를 읽기 쉬운 형태로 보여 줍니다. 담당자는 기관·계좌·기간을 수정하고 사유를 남길 수 있습니다. 범위가 같은 요청은 중복 생성하지 않으며, 하나의 제출파일을 근거 없이 여러 계좌 요청의 완료로 처리하지 않습니다.

**증명하는 기간과 발급일은 별개입니다.** 예를 들어 최근 3년의 세무자료를 요청했다면 증명 대상기간과 최근 발급 여부를 각각 확인합니다. 현재 등록된 관공서 서류 기준은 원칙적으로 발급 2개월 이내를 확인하되, 예외와 사건별 요구를 함께 검토하도록 되어 있습니다.

발급 옵션도 요청에 포함합니다. 상세증명 여부, 주소 변동 이력, 전국·모든 세목 조회, 사용자 서명, 본인과 제3자의 주민번호 표시 범위 등 확보된 원문의 조건을 사용합니다.

## 제출 후에는 요청 범위와 대조합니다

제출자료는 명의·서류 종류에 더해 기관, 계좌, 조회 시작일과 종료일, 발급일, 필요한 발급 옵션을 확인합니다. 기간이 짧거나 다른 계좌 자료가 제출되면 부족한 범위를 알려 다시 요청합니다. 거래내역에 처음과 마지막 거래일이 있다는 이유만으로 그 사이의 전체 조회기간이 충족됐다고 추정하지 않습니다.

필수 정보가 읽히지 않으면 확인 대기로 남기고 담당자가 원문과 판독값을 보완할 수 있습니다. 담당자가 현재 원문과 범위를 직접 확인한 자료는 과거 자동 판독 경고만으로 다시 요청하지 않습니다. 고객에게 보여 주는 요청 안내에는 내부 검증 원문이나 직원용 전략 정보를 포함하지 않습니다.

소득유형이나 사건 범위가 바뀌어 필요가 없어진 자동 요청은 철회 사유를 남깁니다. 제출파일과 완료 이력은 보존하며, 사유를 적어 수동 철회한 동일 요청을 자동으로 다시 만들지 않습니다. 기관·계좌·기간 등 범위가 새로 바뀐 경우에는 다시 판단합니다.

## 기준 변경은 확인한 뒤 적용합니다

공식 원문의 변경 여부와 시행일을 정기적으로 확인하고, 담당자는 지식함에서 저장된 본문과 수집 상태를 볼 수 있습니다. 본문을 확보하지 못한 경우에는 오류와 재수집 상태를 표시합니다. 내용이 없는 메뉴 화면을 법령 본문으로 취급하지 않습니다.

법원 기준이 바뀌면 변경된 문장과 필요한 후속 검토를 확인해야 합니다. 새 본문을 수집했다고 서류 요청기간이나 발급 옵션을 바로 바꾸지 않습니다. 검증된 적용 기준이 달라지면 관련 사건의 요청·계산·문서를 다시 확인합니다. 원문 확인에 실패했을 때는 마지막 정상 자료를 유지하면서 실패 사실을 알립니다.

## 근거와 구현 참고

규칙별로 공식 출처 주소, 확인일, 조항·쪽수, 적용 법원과 원문 식별정보를 보관합니다. 현재 법원별 요청 정책의 원문 확인일은 2026년 10월 3일이며 이후 변경 감시 기록과 사건별 적용 판단은 별도로 관리합니다.

- [법원별 요청 정책](../data/court_request_rules.json): 기간·발급 옵션·대체자료·근거와 적용 한계
- [서류 요청 처리](../apps/api/court_rules.py): 범위 분리, 제출 대조, 철회와 이력 보존
- [법령 변경 확인 정책](../data/legal_watch_policy.json): 등록 공식 출처와 확인 주기
- [자동 처리 안내](ax-automation.md): 자료 완비 후 계산·문서 작성으로 이어지는 절차

요청 정책의 재생성은 검토된 매핑을 사용합니다. AI가 읽은 문장을 검토 없이 새로운 제출 의무로 바꾸는 방식은 아닙니다.
