# 제출 자료를 사건 정보로 정리하는 기능

제출된 서류에서 소득·채무·재산·가족·거주 정보를 찾아 계산과 문서 작성에 연결합니다. 숫자만 옮기지 않고 **누구의 자료인지, 무엇을 나타내는 금액인지, 어느 기간의 값인지, 어느 원문에서 확인했는지**를 함께 보관합니다.

직원은 추출된 값과 해당 문서의 쪽·줄·인용문을 대조할 수 있습니다. “원문에서 확인한 사실”, “AI가 의미를 검토한 결과”, “담당자가 확정한 법률 판단”은 서로 다른 상태로 관리합니다. 원문과 숫자가 일치한다는 이유만으로 사건의 법률 판단까지 승인하지 않습니다.

## 자료별로 확인하는 내용

| 자료 | 확인하는 내용 | 연결되는 업무 |
| --- | --- | --- |
| 주민등록·가족관계 자료 | 성명, 주소, 가족 관계, 명시된 가구 구성 | 신청서의 인적 사항, 부양 관련 검토 |
| 재직·건강보험·연금가입 자료 | 근무처, 재직 관련 기간과 표시, 담당 업무 | 소득 유형 확인, 소득증명서 |
| 급여명세·원천징수 자료 | 월·연 구분, 세전 금액, 공제, 실수령액 | 수입 목록, 소득 대조, 계산 입력 |
| 부채증명 자료 | 채권자, 대출 식별정보, 원금, 이자, 합계 | 채권자목록, 채무 집계 |
| 계좌통합조회·은행거래내역 | 금융기관, 계좌, 잔액 기준일, 월별 급여·생활비·상환 거래 | 재산목록, 소득·지출 대조 |
| 지적조회·지방세·보험 자료 | 원문에 표시된 보유 여부, 보험 계약과 해약환급금 | 재산 확인과 추가 검토 |
| 거주확인·생활비·채무 경위 진술 | 보증금·임차료·무상거주, 실제 지출, 당사자가 설명한 차입 경위 | 수입·지출 목록, 진술서의 근거 |

이 표는 현재 확인하는 항목의 범위입니다. 모든 기관의 모든 서식을 자동으로 해석한다는 뜻은 아닙니다. 당사자의 설명은 진술 자료로 구분하며, 금융기관 증빙이나 확정된 법률 판단으로 바꾸어 취급하지 않습니다.

## 헷갈리기 쉬운 표현과 금액의 구분

**“급여외 소득 없음”은 무직이라는 뜻이 아닙니다.** 급여 외 추가 소득이 없다는 문장에서 “소득 없음”만 떼어 무직으로 분류하지 않습니다. “사업소득 없음”, “현재 무직 아님”도 문장 안의 대상과 부정 범위를 확인합니다.

**월급과 연 소득, 세전과 실수령액을 따로 읽습니다.** 예를 들어 월 실수령액 320만원과 연간 총급여 4,260만원이 함께 있으면 같은 소득값으로 합치지 않습니다. 월 실수령액과 연간 합계·공제를 각각 보관합니다. 원문에 월평균이 명시되지 않은 연간 금액을 임의로 월소득에 넣지 않습니다. 작성용 연간 환산값을 만드는 경우에는 원문 값과 계산으로 만든 값을 구분합니다.

**같은 계좌를 두 번 더하지 않습니다.** 계좌조회서와 거래내역서에 같은 예금 240만원이 나와도 자산을 480만원으로 만들지 않습니다. 금융기관·계좌·잔액 기준일을 대조하며, 계좌를 특정할 수 없는 진술상의 잔액은 별도 계좌로 더하지 않고 상세 자료와 비교합니다. 늦게 발급된 문서라고 잔액까지 최신인 것은 아니므로 발급일과 잔액 기준일도 구분합니다.

**한 파일에 여러 채권자가 있어도 채무를 나누어 관리합니다.** 쪽별 채권자와 대출 식별정보를 유지하고 원금·이자를 각각 대조합니다. 같은 은행의 서로 다른 대출도 구분합니다. 일부 대출을 식별하지 못했거나 금액이 충돌하면 확인된 부분합을 전체 채무처럼 표시하지 않습니다. 가족에게 빌렸다는 진술과 잔액도 따로 남기며 금융기관 채무에 임의로 합산하지 않습니다.

**“없음”과 “알 수 없음”은 다릅니다.** 서류에 부양가족 없음, 보유 없음 등이 명시된 경우에는 그 표현을 근거로 남깁니다. 서류가 없거나 해당 항목을 읽지 못한 경우에는 0원이나 없음으로 채우지 않습니다. 가구원 수가 확인되어도 법률상 인정되는 생계비 인원까지 자동 확정하지 않습니다.

## 계산과 초안까지 이어지는 원문 근거

각 항목에는 원문 인용, 문서명, 쪽·줄 위치를 연결합니다. 금액에는 원문에 있는 단위와 월·연·기간 구분을 함께 보관합니다. “단위: 천원” 같은 표시로 금액을 환산한 경우에도 환산의 근거를 남깁니다. 은행 거래표의 같은 행을 중복 추출해 다시 합산하지 않습니다.

초안을 만들 때는 원문을 다시 대조해 값과 집계 근거가 현재 자료에 맞는지 확인합니다. 필요한 서류의 추출과 검토, 추출값 전체의 원문 대조가 끝나지 않으면 새 문서를 만들지 않고 재확인을 기다립니다. 이미 확인한 값과 이전 작성본은 보존합니다.

전체 원문 대조를 마친 뒤에는 법률 판단이나 후속 문서 검토가 미완료여도 근거가 확인된 소득·채무·예금 등의 사실을 지우지 않습니다. 대신 충돌하는 값, 확인되지 않은 수치, 생계비 인정·면제재산·비용 같은 법률 판단은 공란이나 보완 항목으로 남깁니다.

이렇게 정리한 내용은 [법원 서식의 작성값과 근거 별지](court-forms.md)에 연결됩니다. 사실이 잘 옮겨졌는지와 법률적으로 사용할 수 있는지는 [문서 검토·최종 승인](document-workflow.md)에서 다시 확인합니다.

## 확인한 범위와 한계

2026년 10월 4일, 서로 다른 가상사건 두 건의 원본 자료를 **각각 15종씩** 처리했습니다. 첫 자료에서는 119개, 두 번째 자료에서는 123개 항목을 확인했고, 각 사건의 7종 PDF에 원문 인용과 함께 모두 보존되는지 대조했습니다. 두 번째 자료에는 담당 업무 항목까지 포함합니다.

월소득·예금·채무 원금·이자·총액·자료에 나타난 자산·생활비·가구원·소득 유형·근무처와 12개월 거래내역도 대조했습니다. 테스트의 기대값은 결과 비교에만 사용했으며 실제 추출 입력에는 원본 파일을 전달했습니다. 이 결과는 정해진 가상자료의 항목 보존 검증이며, 실제 모든 서식의 판독 정확도나 법원 인가 가능성을 뜻하지 않습니다.

로컬 검사 기록: 첫 자료 추출 대조: `reports/ocr-audit/fresh_start-extraction.json`, 두 번째 자료 추출 대조: `reports/ocr-audit/ocr_retest-extraction.json`, 첫 7종 문서 대조: `reports/ocr-audit/fresh_start-generated-documents.json`, 두 번째 7종 문서 대조: `reports/ocr-audit/ocr_retest-generated-documents.json`.

운영·개발 참고: 원문 항목 읽기는 [문서 추출](../apps/api/document_facts.py), 중복·충돌·집계 대조는 [사건 정보 연결](../apps/api/evidence_mapping.py)이 담당합니다. 문서별 원문·기간·단위·식별정보를 보존해야 하며, 내부 식별자만으로 다른 문서의 값을 같은 항목으로 합치지 않습니다.
