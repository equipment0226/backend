# 처음부터 직접 테스트하기

2026년 10월 4일 마지막 초기화 기준으로 **계정 3개와 사건 0건**에서 시작합니다. 기존 사건은 백업 후 비우고, 사용자가 이하늘 사건을 직접 신청할 수 있도록 신규 사건을 미리 만들지 않았습니다. 법률 자료와 서식, 로그인 계정은 유지합니다.

상담과 제출은 같은 사람의 자료로 진행해야 합니다. [이하늘 제출용 PDF 묶음](../examples/ocr_retest_submission.zip)도 준비되어 있습니다. 별도로 준비한 박지우 자료는 공식 서식의 기재 항목을 대조하기 위한 PDF **29개·53쪽**이며, 아래 금액 비교표는 그 박지우 자료를 기준으로 합니다. 서로 다른 사례의 자료를 한 사건에 섞지 않습니다.

## 접속과 계정

| 화면 | 주소 | 아이디 | 비밀번호 |
| --- | --- | --- | --- |
| 고객 | http://localhost:5173 | customer | customer |
| 직원 | http://localhost:5174 | staff | staff |
| 변호사 | http://localhost:5174 | lawyer | lawyer |

직원과 변호사를 함께 확인하려면 서로 다른 브라우저나 브라우저 프로필을 사용하세요. 서버가 꺼져 있다면 프로젝트의 `start-local.cmd`를 실행합니다. 자동 판독·검토를 이용하려면 로컬 AI 서비스도 실행되어 있어야 합니다. 위 계정은 로컬 테스트용입니다.

## 1. 고객이 상담 신청하기

고객으로 로그인하고 **내 사건 → 상담·신청 시작**에서 이름과 신청 내용을 직접 입력합니다. 이하늘로 테스트한다면 그 사례의 상담문과 제출자료를 사용합니다. 신청한 뒤 직원의 **전체 사건**과 고객의 **내 사건**에서 같은 신청을 확인합니다. 처음에는 **상담 신청 접수** 상태이며, 상세 상담 전에 모든 서류가 자동 요청되지 않는 것이 정상입니다.

**가상 상담 예시 불러오기** 버튼의 기본 예시는 박지우입니다. 이하늘을 직접 신청할 때는 이 예시를 섞어 넣지 않습니다. 예시 버튼은 입력만 채우므로 자료 활용 동의와 신청은 직접 진행해야 합니다.

## 2. 직원이 세부상담 기록하기

직원의 **상담 기록**에서 고객이 남긴 신청을 확인하고 **세부 상담 요청**을 보냅니다. 고객 계정의 알림과 **담당자 문의**에 안내가 도착하는지 확인합니다.

고객 답변이나 통화에서 확인한 내용을 담당자가 질문별 답변과 종합 기록에 정리합니다. 박지우 예시를 선택한 경우에만 [박지우 세부상담 연습문](../examples/court_ready_fixture/staff_consultation.txt)을 사용합니다. 최초 신청문과 상세 상담 기록은 구별합니다. 자료 활용 동의를 확인하고 **상담 완료·추출 시작**을 누르면 이 기록을 기준으로 필요한 서류를 선정합니다.

## 3. 고객이 요청별 서류 제출하기

고객의 **내 사건 → 제출 서류 → 연습자료 ZIP**에서 현재 사건 이름에 맞는 연습자료를 내려받습니다. 이하늘 사건이면 이하늘, 박지우 사건이면 박지우의 제출용 PDF만 들어 있습니다. 직원의 **자료 검증 → 가상자료 ZIP**도 같은 방식으로 선택합니다. 등록되지 않은 이름에는 다른 사람의 자료를 대신 제공하지 않습니다. 자료별로 직접 첨부하거나 **한 번에 넣기**로 ZIP을 그대로 제출할 수 있습니다.

- [박지우 제출용 PDF ZIP](../examples/court_ready_fixture_submission.zip)
- [박지우 전체 설명·검산 자료 ZIP](../examples/court_ready_fixture_bundle.zip) — 일괄 제출용이 아닙니다.
- [상담 신청문](../examples/court_ready_fixture/application.txt)
- [자료 안내문](../examples/court_ready_fixture/README.txt)

고객이 제출할 파일은 `documents` 폴더의 PDF 29개입니다. 급여명세 12개월을 한 파일로 묶고, 금융기관·계좌별로 자료를 나눴습니다.

| 구분 | 포함한 서류 |
| --- | --- |
| 신분·가족 | 주민등록표 등본·초본, 가족관계증명서, 혼인관계증명서 |
| 금융·채무 | 계좌통합조회, 금융기관 3곳의 부채증명, 은행 2곳의 거래내역 |
| 소득·재직 | 원천징수영수증, 소득금액증명, 급여명세 12개월, 재직·근로조건, 건강보험, 연금 가입내역 |
| 재산·거주 | 임대차계약, 보증금·차임 납부확인, 보험조회·해약환급금, 예상퇴직금, 부동산·자동차 조회, 지방세·국세 자료 |
| 경위·생활 | 채무발생·생활현황 진술, 월 생활지출, 납부·결제내역, 과거 치료비·차입금 사용내역 |

요청 카드의 종류·기관·계좌·기간을 확인하고 맞는 파일을 제출합니다. **임대차·보험·생활지출·채무경위 자료도 빠뜨리지 마세요.** 한 요청에 여러 파일을 골라 함께 올릴 수 있고 추가 자료도 이어서 제출할 수 있습니다. 같은 파일을 여러 번 올려도 다른 종류의 증빙을 대신하지 않습니다. 한 묶음에서 일부 파일이 실패하면 그 묶음 전체를 확인해 다시 제출합니다. 이전에 정상 접수한 파일은 보존됩니다.

해당 자료의 요청 카드가 없다면 **제출 서류 → 다른 자료 제출 → 별도 참고 자료**로 올릴 수 있습니다. 제출 후 담당자가 사건에 필요한 자료인지와 내용을 확인합니다.

기관이나 계좌가 미확정이면 담당자가 자료 원문을 대조해 **가상새봄은행·가상온유은행**, 두 연습 계좌, **가상다온물류 주식회사**로 연결합니다. 급여소득만 있는 상담에서 사업자등록증이나 매출 자료가 불필요하게 요청되지 않는지도 확인할 수 있습니다.

PDF 밖의 `manifest.json`, `financial_reconciliation.json`, 거래내역 CSV와 `court_form_coverage.json`은 검산·지원 범위 확인용입니다. **`legal_review_inputs.json`은 가상의 법률 판단을 연습하는 참고안이며 증빙으로 제출하면 안 됩니다.** 변호사가 별도로 근거와 적용 여부를 확인해야 하며, 자동으로 확정하거나 제출 조건을 통과시키는 파일이 아닙니다.

## 4. 검증과 자동 작성 확인하기

직원은 **자료 검증** 상단에서 요청 서류, 제출된 자료, 요청 범위 충족과 서류 검증 현황을 먼저 확인합니다. 철회하거나 더 이상 필요하지 않은 요청은 현재 준비할 건수에서 제외하며, 상세 이력에는 남습니다.

**받은 서류**의 각 카드에는 추출 대기·진행·완료·오류가 표시됩니다. 진행 중인 자료에는 작은 회전 표시와 처리한 쪽수가 나타납니다. 한 서류가 완료됐다는 이유로 다른 서류까지 완료로 표시하지 않습니다.

1. 해당 카드의 **이 서류의 추출내용 보기**를 엽니다. 제출 원문과 그 서류에서 읽어낸 값, 인용문·쪽·행을 함께 확인합니다.
2. 맞는 값은 그대로 두고, 틀린 항목만 **값 정정**으로 수정하거나 제외합니다. 항목마다 채택 버튼을 누를 필요는 없습니다.
3. 인물·요청 범위·전체 추출내용을 대조하고 확인 이유를 적은 뒤 **이 서류 검토 완료**를 한 번 누릅니다. 서류 검증과 해당 서류의 추출 항목 확인이 함께 저장됩니다.

추출이 끝나지 않았거나 오류가 있으면 내용을 열어볼 수 있지만 검토 완료는 저장할 수 없습니다. 다른 화면에서 자료가 바뀌면 이전 버전의 검토를 그대로 덮어쓰지 않으며, 입력한 정정 내용을 확인한 뒤 최신 자료를 다시 열 수 있습니다. 원문 파일과 이전 추출·작성 이력은 보존합니다.

모든 필요한 서류의 추출과 검토가 끝나야 다음 단계로 진행합니다. 같은 요청에 여러 원본이 있으면 마지막 한 파일만 완료됐다고 다음 단계로 넘어가지 않습니다. **사건 개요의 진행단계**에서 원문 대조, 계산·쟁점 분석, 1차 문서 자동 작성, AI 문서 검토를 확인합니다. 자료 검증·법률쟁점·문서결과 화면에 전체 자동화 카드를 반복 표시하지 않습니다. 처리 시간은 자료와 로컬 실행 환경에 따라 달라집니다. 서류 확인은 이후 법률 판단이나 작성본 최종 승인을 대신하지 않습니다.

**법원 서식**에서는 파일이 생겼는지만 확인하지 말고, **작성본 PDF**의 본문·표·근거별지를 직접 읽습니다. **작성 내용·AI 검토 확인**에서 원문에서 확인한 값, 미확정 항목, 법률 판단 제안을 구별합니다. 잘못된 내용을 보완하면 **새 버전 작성 → AI 문서 재검토**로 이어지고 이전 작성·검토 이력은 보존됩니다.

박지우 사례에서 비교할 주요 값은 다음과 같습니다.

| 항목 | 확인할 값 |
| --- | --- |
| 월 급여 | 지급총액 390만원 − 공제 45만원 = 실수령 345만원 |
| 최근 급여 12개월 | 2025년 10월~2026년 9월 실수령 합계 4,140만원 |
| 2025년 귀속 원천징수 | 지급총액 4,230만원, 과세급여 3,990만원; 최근 12개월 급여와 기간이 다름 |
| 채무 | 원금 6,750만원 + 유예된 과거 이자 150만원 = 6,900만원 |
| 예금 | 두 계좌 잔액 180만원 + 70만원 = 250만원 |
| 거주 | 보증금 1,200만원, 월세 65만원 |
| 보험·퇴직금 | 해약환급금 240만원, 예상퇴직금 공제 전 17,508,189원 |
| 관측 재산 | 공제 전 합계 34,408,189원; 법률상 청산가치와 구별 |
| 실제 월 생활지출 | 165만원; 대출 원리금 상환은 별도 |
| 가족 | 1인가구, 부양가족 없음 |

귀속연도가 다른 원천징수액을 현재 월 실수령액으로 바꾸어 쓰면 안 됩니다. 본인 계좌 사이의 월 111만원 이체는 소득·지출로 중복 합산하지 않으며, 예금·보험환급금을 생활비와 혼동하지 않습니다. 실제 생활지출과 법률상 인정 생계비, 퇴직금 총액과 법률상 공제도 별도로 검토합니다.

자동 검토가 어려운 부분은 사유를 남기고 담당자 확인으로 이어집니다. 원문에서 확인한 사실을 바탕으로 초안을 만들 수 있지만, 검토하지 못한 항목까지 통과했다고 표시해서는 안 됩니다.

## 5. 변호사 검토와 제출 준비 확인하기

변호사 계정에서 **문서·결과**를 열고 작성본 전체, 보완 사유, 제출 조건을 확인합니다. 조건을 충족한 문서는 제출 패키지로 준비하고 변호사가 최종 승인합니다. 자세한 순서는 [문서 검토와 제출 기록](filing-review.md)을 참고하세요.

등록된 필수 작성 항목이 모두 채워져도 원본 서식의 모든 칸과 선택사항이 확정됐다는 뜻은 아닙니다. 원래 서식에 남은 빈칸, 별지로 이어진 기관·계좌와 금액, 증명일·서명·선택 문구를 직접 확인합니다. 연습용 법률 가정을 넣어 별도로 만든 배치 검사 PDF도 실제 사건의 승인 문서가 아닙니다.

가상자료에는 무효 연습용 인적사항을 넣었으며 실제 서명·관인·직인이 없습니다. 각 PDF에도 가상 연습자료이며 실제 제출할 수 없다고 표시했습니다. 실제 제출요건과 확정하지 않은 법률 판단은 보완 대상으로 남는 것이 정상입니다. 테스트를 끝내기 위해 실제 정보나 접수증을 만들어 넣지 마세요. 앱은 법원으로 자동 전송하지 않으며, 실제 외부 제출 이후에만 접수증과 제출 기록을 연결합니다.

## 개발자가 다시 확인하는 방법

새 박지우 자료의 추출과 작성 연결은 다음 명령으로 확인합니다. 실제 고객 사건과 분리된 자료를 사용하며, 기대값은 검사 도구에만 제공하고 추출기에 답으로 전달하지 않습니다.

```powershell
python -X utf8 scripts/audit_court_ready_fixture.py
```

결과는 `reports/court-ready-fixture/extraction.json`에 남습니다. 같은 폴더의 `source-visual-review.json`은 새 원본 PDF의 표 배치·가상 표시와 거래 잔액 대조 기록입니다. 법률 판단 예시를 자동 승인값으로 사용하는 검사가 아닙니다.

마지막 초기화 후의 실제 로그인·화면·ZIP 다운로드 확인은 `reports/browser-fresh-start.json`에 기록했습니다. 세 역할에서 사건 0건을 확인하고, 예시 불러오기가 신청이나 동의를 대신하지 않는지도 확인합니다. `reports/browser-court-ready-intake.json`은 앞서 박지우 사건을 준비했던 시점의 기록입니다. 고객이 테스트를 진행한 뒤의 사건 상태는 이 시작 기록과 달라질 수 있습니다.

이전 가상사례와 비교할 때는 다음 검사를 사용합니다.

```powershell
python -X utf8 scripts/audit_document_extraction.py
python -X utf8 scripts/audit_generated_documents.py
```

## 연습한 사건 정리하기

사건을 삭제해야 할 때만 아래 관리 도구를 사용합니다. 먼저 `scripts/reset_test_case.py 사건ID`로 삭제 범위를 확인합니다. `--apply`를 붙이면 서버가 종료된 상태에서 백업을 만들고 지정한 가상 사건의 원본·작성본·이력·사건별 학습 기록을 정리합니다. 계정, 다른 사건, 공식 법령, 실행 설정은 유지합니다.

정리 결과는 `reports/test-case-reset.json`, 백업은 `.local/backups`에 남습니다. 백업은 현재 사건 검색·학습에 사용되지 않습니다. 계정까지 지우는 전체 초기화 도구는 사건 하나를 정리할 때 사용하지 않습니다. 새 시작 설정은 `.local/start-profile.json`에 저장되므로 재실행해도 예전 시연 사건을 자동으로 만들지 않습니다.
