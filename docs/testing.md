# 처음부터 직접 테스트하기

로컬 새 테스트 프로필은 고객이 직접 상담을 신청해야 사건이 생긴다. `.local/start-profile.json`의 `fresh` 설정으로 예전 시연 사건을 재생성하지 않는다. 기존 김새봄 자료는 추출 회귀용으로 보존하고 새 수동 테스트에는 이하늘 자료를 사용한다.

## 접속과 계정

| 화면 | 주소 | 아이디 | 비밀번호 |
| --- | --- | --- | --- |
| 고객 | http://localhost:5173 | customer | customer |
| 직원 | http://localhost:5174 | staff | staff |
| 변호사 | http://localhost:5174 | lawyer | lawyer |

역할별 브라우저나 탭에서 확인한다. API 문서는 http://localhost:8000/docs 이다. 서버가 꺼졌다면 프로젝트의 `start-local.cmd`를 실행한다. 개인정보를 처리하는 로컬 AI 서비스도 실행되어 있어야 한다. 위 계정은 외부 공개용 계정이 아니다.

## 신청부터 진행

1. 고객으로 로그인하고 **내 사건 → 상담 신청 → 가상 상담 예시 불러오기**를 선택한다. 이름 이하늘, 서울회생법원과 상담 내용이 채워진다. 입력을 확인하고 직접 동의·신청한다.
2. 직원으로 로그인하여 새 신청 알림이나 사건 목록에서 사건을 연다. **상담 기록 → 세부 상담 요청**으로 안내한다. 신청 접수 단계에는 자동 추출·서류 요청이 없다.
3. 고객은 알림과 담당자 문의에서 회신한다. 담당자는 세부 상담을 진행하고 종합 메모·질문을 작성한 뒤 **상담 완료·추출 시작**으로 저장한다. 가상 테스트에서는 제공된 상담 예시의 사실관계를 사용한다.
4. 고객의 **연습자료 ZIP**을 받아 압축을 푼다. 요청 카드의 종류·기관·계좌·기간에 맞는 `documents` 파일을 제출한다. **무상거주확인·채무발생및생활비진술도 제출**한다. 중복 파일은 다른 종류의 증빙을 대체하지 않는다.
5. 미확정 기관·계좌는 하늘테스트은행 / `TEST-ACCOUNT-SKY-002`, 하늘테스트물류로 확인한다. 급여소득만 있는 상담에서 사업자등록증·매출 자료가 요청되지 않는지 확인한다.
6. 직원의 **자료 검증**에서 인물·기간·범위와 내용을 확인한다. 필요한 서류 제출·검토가 완료되면 **Case Automation**에서 원문 대조 → 항목 추출 → 계산·전략 → 1차 문서 → AI 검토로 진행한다.
7. **법원 서식**에서 실제 작성 칸과 근거별지, 검토 목록을 확인한다. 오류를 새 버전으로 수정하고 **AI 문서 재검토**를 실행한다. 원문 변경 시 분석도 다시 진행한다.
8. 변호사는 제출 패키지의 최종 검토를 진행한다. 실제 서명·동의·접수증은 합성 자료로 대신하지 않는다. 앱은 외부 법원으로 전송하지 않으며 실제 제출 이후 접수증과 제출 기록을 남긴다.

자료: [연습자료 ZIP](../examples/ocr_retest_bundle.zip), [상담 예시](../examples/ocr_retest/application.txt), [안내문](../examples/ocr_retest/README.txt).

새 사례는 월 실수령 320만원, 총급여355만원·공제35만원, 채무7,200만원(원금6,900만원+이자300만원), 예금240만원, 실제 생활지출160만원, 1인가구·무상거주다. 연금 기준소득355만원을 실수령액으로 사용하면 안 된다. ‘급여외 소득 없음’은 무직을 뜻하지 않는다.

`optional_error_checks`는 명의·기간 불일치를 확인하는 별도 테스트다. 정상 자료와 함께 제출하지 않는다. `manifest.json`과 안내문은 증빙이 아니다. 실제 주민등록번호·전화번호·서명은 의도적으로 없으므로 최종 제출 전 보완 항목으로 남는다.

## 원문과 작성본 대조

`python -X utf8 scripts/audit_document_extraction.py`는 실제 PDF 15종씩을 OCR로 읽고 문서별 항목, 정확한 원문 인용, 통합 금액, 은행12개월 행을 대조한다. 기대값은 시험 도구에만 있으며 추출기에는 전달하지 않는다.

- 등본·가족관계: 명의·주소·가구원 수와 혼인·자녀·부양 진술
- 소득·재직·건강보험·연금: 총급여/공제/실수령, 연간/월간, 재직 상태와 기준소득
- 채무·계좌: 채권자·대출별 원금/이자, 계좌·기준일별 잔액, 중복 합산 방지
- 지적·지방세·보험·거주: 조회 범위, 명시된 없음/0원, 보증금·차임·소유 여부
- 경위 진술: 채무의 시기·사용처·상환 사정, 실제 지출과 법률상 인정 생계비 구별

`scripts/audit_generated_documents.py`는 추출 검사에서 저장한 격리 사건으로 실제7종 PDF를 만들고 원본 칸에 배치된 값 및 근거별지의 관측 보존을 검사한다. 파일7개 생성만으로 내용 검증 완료를 판정하지 않는다. 실제 로컬 모델 진술 결과를 `--narrative 파일경로`로 대조할 수 있으며 이 검사에서 최종 AI 문서 승인·법원 제출을 가장하지 않는다.

결과는 `reports/ocr-audit/*-extraction.json`, `*-generated-documents.json`에 기록한다. 실제 OCR 품질·남은 식별자 충돌은 [OCR 설명](ocr.md), 항목 해석과 집계 규칙은 [문서 추출 설명](document-extraction.md)을 참고한다. 실제 모든 기관의 서식 정확도를 보증하는 벤치마크는 아니다.

## 데이터 정리

`scripts/reset_test_case.py 사건ID`는 지정한 가상 사건의 삭제 범위를 조회한다. `--apply`는 API가 종료된 상태에서 검증한 백업을 만들고 해당 사건·원본·작성본·이력·사건별 학습 기록만 제거한다. 계정·다른 사건·공식 법령·OCR 모델·환경설정을 유지한다. 정리 결과는 `reports/test-case-reset.json`에 남는다.

과거 전체 초기화는 `reports/fresh-start-reset.json`의 별도 기록이다. `reset_fresh_start.py`는 계정까지 초기화하므로 사건 하나만 지울 때 사용하지 않는다. 백업은 `.local/backups`에 격리되며 현재 검색·학습에 사용되지 않는다.
