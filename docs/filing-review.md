# 작성 문서 검토와 제출 기록

자료 제출과 검토가 끝나면 확인된 사실을 바탕으로 1차 문서를 자동 작성하고 AI가 작성 내용과 근거를 대조합니다. 직원·변호사는 이 결과를 보완하고, 변호사가 최종 제출 문서 전체를 승인합니다. 실제 법원 제출은 담당자가 외부 전자소송 등에서 진행하며, 앱에는 승인본과 접수증을 연결해 이력을 남깁니다.

직원·변호사 화면은 **http://localhost:5174**입니다. 사건을 연 뒤 **법원 서식**과 **문서·결과** 메뉴를 사용합니다.

## 1차 작성본 확인

**법원 서식**에는 작성된 사건 문서를 먼저 보여주고, 아래에 공식 빈 서식을 따로 모아 둡니다. 현재 지원하는 기본 작성본은 다음 7종입니다.

- 개인회생절차 개시신청서
- 재산목록
- 수입 및 지출에 관한 목록
- 진술서
- 변제계획안
- 급여소득 증명서
- 개인회생채권자목록

각 카드에서 **작성 내용·AI 검토 확인**으로 항목별 값과 검토 사유를 읽고, **작성본 PDF**로 실제 본문과 표의 배치를 확인할 수 있습니다. 원문에서 확인한 값에는 제출 자료의 쪽·행과 인용 근거를 연결합니다. 본문 칸에 담기 어려운 값과 세부 근거는 별지에 보존합니다. 이전 작성본은 변경 이력에서 다시 볼 수 있습니다.

원문에 적힌 금액과 법률상 인정되는 금액은 구별합니다. 예를 들어 실제 생활지출이 확인되어도 인정 생계비가 확정된 것은 아닙니다. 미확정 값은 임의의 숫자나 0원으로 채우지 않고 보완 대상으로 남깁니다.

AI 검토가 완료되지 않더라도 원문에서 확인한 사실은 지우지 않습니다. 이 경우 작성본에 의미 검토가 필요한 상태를 표시하며, 진술서에는 확인된 사실을 정리한 초안을 제공할 수 있습니다. 이를 검토를 통과한 완성 문서로 취급하지 않습니다.

## 잘못된 내용 보완하기

직원·변호사는 원문, 추출값, 법률 계산, 작성본 중 어느 단계에서 문제가 생겼는지 확인합니다. 단순히 숫자가 원문에 있다는 이유만으로 맞다고 판단하지 않고, 월 소득과 연 소득, 총급여와 실수령액, 자산과 생활비의 의미까지 구별해 검토합니다.

1. 원문이나 추출값이 잘못됐다면 **자료 검증**에서 확인·보완합니다. 새 자료가 반영되면 관련 분석과 작성본도 다시 검토합니다.
2. 작성 내용을 바꾸려면 **새 버전 작성**을 사용합니다. 이전 문서는 보존됩니다.
3. 변경한 문서에서 **AI 문서 재검토**를 실행하고 발견 사항을 확인합니다. 직접 수정한 문서는 별도 검토가 필요한 상태로 시작합니다.
4. **문서·결과**에서 남은 보완 사유와 제출 준비 조건을 다시 확인합니다.

이미 승인하거나 제출 기록에 연결한 문서는 새 버전으로 수정해야 합니다. 수정 전후 내용과 검토 사유를 남겨 어떤 근거로 바뀌었는지 확인할 수 있습니다.

## 제출 패키지 준비와 변호사 최종 승인

**문서·결과 → 보완·최종 승인·제출 처리**에서 최신 7종을 한 묶음으로 준비합니다. 화면에 문서별 검토 상태와 아직 해결하지 않은 사유가 표시됩니다. 다음 조건을 확인해야 **제출 패키지 준비**로 진행할 수 있습니다.

- 상담과 필요한 서류 검토가 완료되고 미결 보완 요구가 없을 것
- 현재 자료를 반영한 공식 작성본과 검증된 계산이 연결되어 있을 것
- 필수 빈칸이나 출력 넘침을 보완하고, 원본 서식과 작성값이 맞을 것
- 현재 PDF의 AI 대조를 통과하고 검토한 파일이 그대로 유지될 것
- 적용 법률 변경으로 생긴 확인 사항을 검토했을 것

7종은 제품이 지원하는 기본 묶음입니다. 개별 법원이나 사건에서 추가 자료를 요구할 수 있으며, 지원하는 공식 서식이 없는 관할은 제출 준비가 제한됩니다.

패키지를 준비한 뒤에는 변호사가 **변호사 최종 승인**을 진행합니다. 서명·날인, 법률상 진술과 동의, 본문의 빈칸, 별지 전체, 계산 판단, 개별 제출요건을 확인하고 승인 근거를 남깁니다. AI의 항목 대조는 이 최종 검토를 대신하지 않습니다.

승인 후 화면은 **제출 준비**로 바뀝니다. **제출 문서 ZIP**으로 수임번호와 서류명이 붙은 파일을 받을 수 있습니다. 자료·판단·작성본·검토 결과가 바뀌면 이전 승인과 일치하는지 다시 확인하며, 필요한 경우 새 패키지로 재승인합니다.

## 외부 제출 후 접수증 남기기

담당자가 실제 제출을 마친 뒤 **외부 제출 후 접수증 등록**에서 접수증과 법원 사건번호를 입력합니다. 접수증의 당사자, 사건번호·관할, 승인한 문서와의 관계를 확인해야 합니다. PDF·TXT·PNG·JPG 파일을 최대 10MB까지 받을 수 있으며, 읽을 수 없는 자료는 보완이 필요합니다.

등록한 접수증을 선택하고 **법원 제출 기록**을 남기면 승인본과 접수증이 연결됩니다. 접수증은 고객의 소득·재산 증빙과 별도로 보관하며, 등록 때문에 기존 계산이 바뀌지 않습니다. 이후에도 접수증 원문과 제출 이력을 확인할 수 있습니다.

현재 외부 법원으로 자동 전송하는 기능은 없습니다. **법원 제출 기록 완료**는 실제 접수증을 연결한 내부 기록이며, 법원의 인가나 면책을 의미하지 않습니다.

## 확인 자료와 개발 검증

로컬 검사 기록 `reports/ocr-audit/generated-visual-review.json`에는 가상사례의 실제 7종 35쪽을 확인한 결과가 있습니다. 채권자목록의 표 경계와 별지 줄 겹침을 수정한 뒤 다시 확인했습니다. 필수 정보나 법률 판단이 남아 있는 초안이므로, 이 검사를 통과한 것과 제출 준비 완료는 구별합니다. 검사 기록은 Git에 포함하지 않습니다.

제출 준비·권한·접수증 연결을 확인하는 개발 시험은 다음과 같습니다. 격리된 가상자료로 실행하며 실제 법원에 전송하지 않습니다.

```powershell
python -X utf8 -m unittest tests.test_filing_gate tests.test_filing_api -v
```

세부 연동 규격은 실행 중인 서버의 http://localhost:8000/docs 에서 확인할 수 있습니다.
