# 사건 개요에서 준비 상태와 보완 방향을 확인합니다

사건 개요는 지금까지 만든 결과를 길게 펼쳐 놓는 화면에서, **어디까지 준비됐고 다음에 무엇을 확인하면 되는지** 살펴보는 대시보드로 바뀌었습니다. 자료를 읽은 정도와 법률상 요건을 충족한 정도는 서로 다른 문제이므로 따로 보여 줍니다.

## 네 가지 지표를 따로 봅니다

| 지표 | 어떤 자료를 보나요? | 어떻게 읽으면 되나요? |
| --- | --- | --- |
| 주요 항목 추출 | 현재 사건에 적용하는 법원 서식의 주요 작성 칸과 제출자료에서 읽은 값 | 여러 서식에 반복되는 같은 항목은 한 번만 셉니다. 읽기를 마친 값과 담당자가 확인한 값도 구분합니다. |
| 정량 요건 충족 | 확인된 소득·채무·재산, 사건별 법률 판단과 현재 계산 | 충족·미충족·판단 대기·해당 없음으로 나눕니다. 모르는 값은 0원이나 위반으로 바꾸지 않습니다. |
| 보완이 필요한 위험 요소 | 계산으로 확인된 한도 초과나 변제액 부족 등 | 실제 미충족 요건의 개수입니다. 서류가 아직 없어서 판단할 수 없는 항목은 옆에 따로 표시합니다. |
| 인가 확률 | 검증된 개별 사건 예측모델의 유무 | 현재는 **예측 보류**입니다. 추출률이나 요건 충족률을 임의의 인가 확률로 바꾸지 않습니다. |

표시된 추출률은 등록된 서식의 주요 항목을 기준으로 합니다. 모든 법원·재판부의 모든 요구를 빠짐없이 확보했다는 뜻은 아닙니다. 급여소득이 확인되지 않은 사건에 급여 전용 서식의 빈칸을 모두 부족 항목으로 더하지도 않습니다. 채권자가 여러 명이면 확인해야 할 채권자별 항목도 늘어납니다.

서명, 날짜와 진술서 작성, 부양인원·공제액처럼 담당자의 판단이 필요한 칸은 원문에서 읽을 항목과 구분합니다. 파일 수가 많다는 이유로 추출률이 높아지거나, 같은 사실이 여러 서류에 있다는 이유로 중복 점수를 얻지 않습니다.

## 숫자를 누르면 근거와 다음 작업으로 이어집니다

지표를 누르면 서식별 확인 항목, 충족하지 못한 요건, 판단을 기다리는 이유를 볼 수 있습니다. 보완 내용에는 관련 화면으로 이동하는 동작을 붙였습니다. 자료의 문제는 자료 검증으로, 금액과 법률 판단의 문제는 법률계산으로 이어집니다.

보완 목록은 다음처럼 나뉩니다.

- **서류 보완:** 어느 자료의 어떤 내용이 아직 없거나 읽기를 마치지 못했는지 알려 줍니다.
- **법률 검토:** 확인된 수치가 어느 기준에 부족하거나 초과하는지, 판단에 어떤 입력이 더 필요한지 설명합니다.
- **추가 소명:** 실제 지출, 퇴직급여 종류, 재산 처분의 경위 등 판단을 돕는 자료와 확인 순서를 제안합니다.

전체 자동 처리 이력은 개요에서 펼쳐 볼 수 있습니다. 자료 검증 화면은 요청한 자료·받은 원문·추출값 확인에 집중하도록 구성합니다.

## 법률쟁점은 같은 사실과 같은 공개 근거를 사용합니다

법령과 공개 사례는 제목만 저장하지 않고 본문, 출처, 적용 법원과 절차 단계를 연결합니다. 그 안에서 **법률 요건 → 관련 쟁점 → 공개 판단 → 확인할 증빙**의 관계를 정리합니다. 이것이 화면과 전략 검토가 함께 사용하는 법률 지식의 연결 구조입니다.

가령 친족에게 먼저 변제한 사정이 확인되면 해당 쟁점을 다룬 공개 판단과 변제 경위·대금 흐름에 관한 증빙을 찾습니다. 반면 그 사정이 없는 모든 사건에 같은 판례를 붙이지 않습니다. 전국에 적용하는 대법원 판단을 서울회생법원의 인가 성공사례라고 부르거나, 인가 후 폐지·면책 사건을 신규 신청의 인가 사례로 사용하는 일도 피합니다.

전략 검토에는 허용된 금액과 분류, 현재 계산, 확인된 공개 근거만 전달합니다. 고객 이름이나 계좌번호, 상담 자유문장과 서류 원문은 외부 검토에 넣지 않습니다. 검토 결과는 **현재 확인된 문제 → 준비할 증빙 → 보완 후 다시 계산할 내용**의 순서로 보여 줍니다. 근거가 부족한 제안은 추가 검토 의견이며 확인된 법률 위반의 개수를 늘리지 않습니다.

재산 매각을 검토할 때도 매각대금의 행방과 남은 재산을 함께 확인해야 합니다. 자산을 팔았다는 이유만으로 청산가치가 줄어든다고 안내하지 않습니다.

## 자료나 법률이 바뀌면 이전 판단을 그대로 보여 주지 않습니다

추가 제출·수정 이후의 자료와 과거 계산이 일치하지 않으면 계산을 다시 기다립니다. 공식 본문이 바뀌어 검토가 필요한 근거도 현재 충족 판단에 그대로 사용하지 않습니다. 최신 사건 자료·계산·법률 근거에 맞는 전략 검토만 현재 결과로 보여 주고 이전 결과는 이력으로 남깁니다.

대시보드를 열거나 새로고침할 때 AI를 새로 호출하지 않습니다. 저장된 사건 자료로 지표를 계산하고 이미 확인한 공개 자료를 연결하므로 조회 자체가 문서 생성 비용을 늘리지 않습니다. 고급 검토는 사건 처리 단계에서 실행하며 같은 자료와 근거에 대한 검증은 기존 비용 관리 규칙에 따라 재사용합니다.

실제 법원 결과가 충분히 쌓이면 유사 사건의 관측 비율을 별도로 참고할 수 있습니다. 그것도 개인의 인가 확률과는 다릅니다. 현재 대시보드는 확인 가능한 준비 상태와 보완 방향을 제공하는 데 사용합니다.

구현 근거는 [서식별 항목·요건 대조](../apps/api/case_assessment.py), [사건과 공개 근거 연결](../apps/api/dashboard_insights.py), [법률 지식 자료](../data/legal_knowledge_graph.json)에 남겨 두었습니다.
