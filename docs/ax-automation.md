# 상담부터 제출 준비까지 이어지는 자동 처리

빚오프는 상담 내용을 정리하고 필요한 서류를 요청한 뒤, 제출자료를 읽어 계산·쟁점 검토·1차 문서 작성으로 이어 줍니다. 직원과 변호사는 같은 내용을 반복해서 옮기는 대신, 근거가 부족하거나 법률 판단이 필요한 부분을 확인하고 보완할 수 있습니다.

자동 처리 중에도 사건 개요에서 현재 단계, 확인한 자료, 처리 결과, 다음 진행 조건을 볼 수 있습니다. 원문과 과거 작성본은 보관하며, 잘못 추출한 값이나 문장은 담당자가 수정할 수 있습니다.

## 상담 신청과 상세 상담을 구분합니다

고객이 상담을 신청하면 먼저 상담 대기 상태로 접수됩니다. 직원이나 변호사가 신청 내용을 보고 세부 상담을 요청하고, 상담 기록을 남긴 뒤에 서류 선정과 분석이 시작됩니다. 고객의 짧은 신청 문구만으로 상세 상담을 대신하거나 서류를 일괄 요청하지 않습니다.

상담을 이미 마친 사건은 담당자가 상담 기록을 직접 등록해 같은 후속 절차로 진행할 수 있습니다. 대기 중 고객이 보낸 메시지와 자료도 사건에 보관됩니다.

## 사건에 맞는 자료를 준비합니다

필요서류는 관할 법원, 현재 소득유형, 금융기관과 계좌, 재산·채무, 확인할 기간을 함께 보고 정합니다. 급여소득만 확인된 사람에게 사업자 전용 자료를 일괄 요구하지 않으며, 급여와 사업소득이 함께 있으면 양쪽 자료를 구분해 준비합니다. 소득유형을 알 수 없으면 상세 상담의 확인 항목으로 남깁니다.

같은 통장 거래내역도 은행·계좌·기간·목적이 다르면 별도 요청으로 표시합니다. 고객은 서류명, 필요한 기간, 발급 방법과 현재 상태를 카드로 확인할 수 있습니다. 필요가 없어진 자동 요청은 철회하되 이미 제출한 파일과 요청 이력은 보존합니다.

고객이 자료를 제출하면 서류 종류뿐 아니라 명의, 기관·계좌, 조회기간, 발급일과 발급 옵션을 대조합니다. 잘못된 자료나 부족한 범위가 확인되면 해당 항목을 재요청하고 고객에게 앱 알림을 보냅니다. 판독이 불분명한 경우에는 담당자 확인으로 연결합니다. 현재 알림은 앱 안에서 제공하며 문자·이메일 발송은 별도 연동이 필요합니다.

## 서류가 준비되면 1차 문서까지 자동으로 진행합니다

유효한 서류 요청의 제출과 검토가 끝나면, 중간 단계마다 승인 버튼을 누르지 않아도 다음 작업을 이어 갑니다.

| 단계 | 처리하는 내용 | 담당자가 확인할 결과 |
| --- | --- | --- |
| 원문 읽기 | PDF의 글자와 스캔 이미지를 읽고 페이지별 내용을 보관합니다. | 판독된 본문과 읽지 못한 부분 |
| 추출값 대조 | 소득·재산·채무·주거·가족관계 등의 값을 원문과 다시 확인합니다. | 값의 출처, 기간, 단위, 원문 인용 |
| 계산과 쟁점 검토 | 확인된 수치로 계산하고 관련 법령·판례를 찾아 사건의 쟁점과 보완 방향을 검토합니다. | 계산안, 적용 근거, 부족한 판단과 자료 |
| 1차 문서 작성 | 편집 가능한 문서와 등록된 공식 서식의 작성본을 만듭니다. | 본문·금액·확인 항목이 담긴 초안 |
| AI 문서 검토 | 작성 문장과 실제 출력된 PDF를 원문·계산·서식과 대조합니다. | 일치 여부와 수정이 필요한 항목 |

숫자를 읽을 때는 월급과 연간 소득, 세전과 실수령액, 원금과 이자, 잔액과 거래금액을 구분합니다. 같은 자료를 두 번 제출했다고 합계를 늘리지 않으며, 서로 다른 금액이 충돌하면 확인을 요청합니다. 은행 잔액의 기준일과 증명서 발급일도 별도로 다룹니다.

일부 값이나 판단이 미확정이어도 확인된 내용으로 1차 초안을 제공합니다. 모르는 금액을 0원으로 채우거나 AI 검토에 실패한 부분을 통과로 표시하지 않습니다. 서류 자체가 부족하거나 명의가 충돌하는 경우에는 자료 확인이 먼저 필요합니다.

## 설명 가능한 진술서와 수정 가능한 작성본을 제공합니다

진술서는 채무가 생긴 경위, 상환이 어려워진 사정, 앞으로의 변제 방향을 확인된 사실과 증빙에 연결해 작성합니다. 관련 판례와 검증된 문서 구성 사례는 설명을 정리하는 참고자료로 사용합니다. 상담 원문을 그대로 붙여 넣거나 다른 사건의 사정을 고객의 사정처럼 쓰지 않습니다.

문장에 쓰인 금액은 수치가 같은지만 확인하지 않습니다. 예금잔액이 생활비로 바뀌거나 연간 소득이 월급으로 표현되지 않았는지도 검토합니다. 작성에 실패하면 원문에서 확인 가능한 사실은 요약으로 담고, 추가로 설명해야 할 경위와 법률 판단을 보완 항목으로 남깁니다. 이 요약은 AI 검토를 통과한 최종 진술서로 취급하지 않습니다.

직원은 작성본의 내용을 고쳐 새 버전을 만들고 AI 재검토를 요청할 수 있습니다. 이전 작성본과 검토 결과는 이력에서 비교할 수 있습니다. 공식 서식 화면에는 작성된 문서를 먼저 보여 주고, 작성에 사용한 빈 원본 서식은 아래에 구분해 둡니다.

## 최종 승인과 제출 기록은 사람이 확인합니다

1차 작성이 끝나면 담당자 보완 단계로 넘어갑니다. 미확정 사실·계산·법률 쟁점을 정리하고, 현재 자료에 맞는 문서 검토를 마친 뒤 변호사가 최종 제출을 승인합니다. 등록된 공식 서식 7종은 개시신청서, 재산목록, 수입지출목록, 진술서, 변제계획안, 소득증명서, 개인회생채권자목록입니다. 필요한 첨부·서명·개별 법원 요구도 함께 확인해야 합니다. 해당 관할의 서식이 충분히 확보되지 않은 경우에는 확인 없이 제출 준비를 완료하지 않습니다.

사건 자료나 적용 법률이 바뀌면 기존 계산·문서·승인을 그대로 사용하지 않고 다시 확인합니다. 추가자료를 요청해 제출받은 사건도 같은 분석과 작성 절차로 돌아갑니다.

현재 서비스의 제출 처리는 **외부에서 법원에 접수한 뒤 접수증을 확인해 내부 이력에 기록하는 기능**입니다. 법원에 직접 전송하는 기능은 없습니다. 접수증은 일반 사건 증빙과 별도로 보관하므로 접수증 등록만으로 승인된 문서가 다시 작성되지는 않습니다.

## 법령 변경과 실제 사건 결과를 다음 검토에 활용합니다

등록된 공식 출처의 본문과 시행일을 정기적으로 확인하고, 변경 사항이 관련 사건에 영향을 주는지 점검합니다. 확인 주기의 기본값은 하루이며 서버와 감시 기능이 실행 중일 때 동작합니다. 분리 배포용 기본 설정에서는 감시가 꺼져 있으므로 운영 시 활성 상태를 확인해야 합니다. 운영 화면에서는 최근 확인과 다음 확인 시점, 변경 원문과 적용 상태를 볼 수 있습니다. 변호사는 확인 주기를 24~720시간 범위에서 조정할 수 있습니다. 수집에 실패하면 마지막 정상 근거를 유지하고 실패 사실을 표시합니다.

자동으로 실행 기준에 반영하는 범위는 엄격히 제한되어 있습니다. 현재는 채무한도와 변제기간의 지정된 수치에 대해 주변 조문과 시행일이 검증된 경우만 자동 적용합니다. 새로운 조건·경과규정·법원 기준의 의미 변화는 법률 검토가 필요합니다. 변경 원문을 수집했다는 이유만으로 모든 요청 규칙과 문서 내용을 자동 확정하지 않습니다.

작성한 문서의 버전과 실제 인가·보정·반려 등의 법원 원문을 연결해 결과를 축적할 수 있습니다. 검증된 같은 사무소·관할의 결과에서 문서 구성과 보완 사항을 찾아 후속 작성 검토에 활용합니다. 가상 사례와 미검증 기록은 제외하며, 모델을 자동 재학습하거나 성공을 보장하는 기능은 아닙니다.

사건 개요의 인가 가능성 참고 지표도 실제 승인 확률과 구분합니다. 검증된 유사 종결 결과가 30건 미만이면 비율을 보여 주지 않습니다. 표본이 모이면 관측된 인가 비율과 오차 범위를 제공하지만, 개별 사건의 확률 예측은 별도로 검증되기 전까지 보류합니다. 30건은 표시를 시작하는 기준이며 예측 정확성을 보장하는 표본 수는 아닙니다.

## 개인정보와 호출 비용을 함께 관리합니다

실명·주민번호·계좌·주소·연락처가 들어 있는 원문 판독과 문서 작성·대조는 로컬에서 처리합니다. 외부 AI를 사용하는 전략 검증에는 허용된 수치와 분류값, 확인된 공개 법률자료만 따로 구성해 전달합니다. 고객의 자유문장이나 문서 원문을 이름만 가리고 그대로 보내는 방식은 사용하지 않습니다.

변경 없는 법률 본문은 다시 내려받지 않도록 확인하고, 같은 입력과 법률 기준으로 통과한 외부 검증 결과는 기본 7일 안에서 재사용합니다. 같은 요청이 동시에 들어오면 호출을 공유하며 단계별 재시도와 하루 호출량에도 한도를 둡니다. 고급 검증의 기본 하루 한도는 20회이며 운영 화면에서 조정할 수 있습니다. 비용 한도나 통신 실패로 검증하지 못한 결과는 확인 대기로 남깁니다.
