# AI가 자료를 읽고 문서를 작성하는 방식

빚오프의 AI는 상담과 서류를 읽고, 추출한 내용이 원문과 맞는지 확인하며, 사건의 쟁점과 문서 표현을 검토합니다. 모든 일을 한 번의 긴 요청에 맡기지 않고 목적별로 나누어 처리합니다. 각 단계는 사용할 근거와 결과 형식이 정해져 있고, 다음 단계로 넘기기 전에 출처와 내용의 일치를 확인합니다.

고객과 담당자 화면에는 특정 모델명이나 내부 지시문 대신 진행 중인 작업, 확인 결과와 보완할 내용을 보여 줍니다.

## 작업마다 다른 자료를 사용합니다

| 작업 | 읽는 자료 | 제공하는 결과 |
| --- | --- | --- |
| 상세 상담 정리 | 담당자가 남긴 상담 기록과 확인할 원문 구간 | 소득유형·재산·채무·과거 이력 등의 후보와 추가 질문 |
| 제출자료 확인 | 요청 범위와 제출 원문 | 명의·서류 종류·기관·계좌·기간·발급 옵션의 일치 여부 |
| 추출값 검토 | 페이지별 원문과 추출된 값 | 금액·단위·기간·의미가 맞는지에 대한 대조 결과 |
| 쟁점·전략 검토 | 개인정보를 제외한 구조화 정보, 계산 결과, 확인된 공개 법률자료 | 확인해야 할 쟁점, 추가자료와 보완 방향 |
| 문서 작성 | 현재 사건의 사실·상담 근거·계산과 관련 법률자료 | 근거가 연결된 한국어 문단과 서식 작성 내용 |
| 작성본 검토 | 작성된 문장·출력 PDF와 독립된 원문·계산·공식 서식 | 근거 없는 표현, 잘못 옮긴 금액, 누락과 출력 문제 |

서류 요청 조건과 법률계산은 정해진 규칙과 산식으로 처리합니다. AI가 반환한 문장만으로 금액을 확정하거나 제출을 승인하지 않습니다. 스캔의 글자를 읽는 작업과, 그 글자가 사건에서 어떤 뜻인지 검토하는 작업도 구분합니다.

## 진술서는 사실을 설명하도록 작성합니다

진술서에서는 채무 발생 경위, 상환이 어려워진 사정, 향후 변제 방향을 이어 설명합니다. 이때 각 문장에 사용할 수 있는 상담 진술과 서류 근거를 제한하고, 필요한 계산과 관련 법률자료를 함께 제공합니다.

관련 판례와 검증된 결과 사례는 어떤 쟁점을 설명하고 무엇을 보완할지 정하는 데 사용합니다. 다른 고객의 진술을 복사하거나 파기환송·면책 사례를 신규 신청의 인가 성공 사례로 바꾸어 사용하지 않습니다. 다른 사건의 문서 구성은 참고할 수 있어도 그 사건의 사정이 현재 고객의 사실이 되지는 않습니다.

작성한 뒤에는 출처가 실제로 존재하는지, 인용과 숫자가 맞는지, 금액의 의미까지 유지됐는지 다시 확인합니다. 예를 들어 240만원이라는 숫자가 같아도 예금잔액을 생활비로 표현했다면 통과시키지 않습니다. 월급과 연간 소득, 채무 원금과 이자도 구분합니다.

검토에서 의미상 오류가 발견되면 해당 지적을 반영해 제한된 횟수 안에서 수정합니다. 추출값 전체의 원문 대조가 시간초과로 끝나지 않았다면 계산과 새 초안 작성을 기다립니다. 전체 대조 이후의 문장 작성·검토가 실패한 경우에는 확인된 사실을 담을 수 있는 부분과 추가 작성·검토가 필요한 부분을 구분합니다. 어느 경우든 실패를 통과로 표시하지 않으며, 담당자가 직접 고친 문장도 재검토 대상으로 남깁니다.

## 개인정보가 있는 작업은 로컬에서 처리합니다

원문 판독, 민감정보를 포함한 추출·계산 입력 정리, 진술 작성과 문서 대조는 로컬 처리 범위에 둡니다. 실명, 주민번호, 계좌번호, 주소, 연락처와 고객의 자유문장을 외부 전략 검증으로 전달하지 않습니다.

외부 AI를 사용하는 검증에는 허용된 숫자·참거짓·분류값만 새로 구성하고, 공개 법률자료는 보관된 원문과 출처를 확인해 제공합니다. 일부 이름만 지운 원문을 그대로 전송하는 방식은 사용하지 않습니다. 문서 안의 명령문도 시스템의 작업 지시로 받아들이지 않으며, API 키는 문서·지시문·화면에 넣지 않습니다.

## 변경과 비용을 관리합니다

자료, 작성 지시, 법률 기준이 달라지면 이전 결과가 여전히 유효한지 다시 확인합니다. 과거 작성본을 덮어쓰지 않고 새 버전과 검토 기록을 남기므로 어떤 근거로 작성했는지 추적할 수 있습니다.

비용을 줄이기 위해 작성할 문단과 관련된 근거를 우선 선택하고, 같은 입력·법률 기준으로 검증을 통과한 결과는 정해진 범위에서 재사용합니다. 외부 고급 검증은 같은 입력·단계의 최초 검증과 보완 검증을 합해 최대 두 번으로 제한하며 하루 호출량도 관리합니다. 확인이 끝난 동일 요청을 중복 호출하지 않고, 한도를 넘으면 대기·검토 상태로 남깁니다.

실제 인가·보정 등 검증된 결과가 쌓이면 문서 구성과 보완 특징을 다음 작성 검토에 활용할 수 있습니다. 이는 출처를 찾아 참고하는 지원 기능이며, 자료가 들어올 때마다 모델을 자동 재학습하거나 인가율을 보장하는 기능은 아닙니다.

## 구현 참고

기존 상담·서류 추출 지시문은 [추출 지시문 목록](../apps/api/prompts/manifest.json)에 등록되어 있습니다. 문서 작성은 [진술 작성 정책](../data/statement_writing_policy.json), 검토는 [원문·전략 검증](../apps/api/verification.py), 개인정보를 포함한 본문 작성은 [근거 기반 작성](../apps/api/grounded_drafting.py)에서 관리합니다.

등록된 지시문을 변경하면 버전과 검증 결과도 관리합니다. 지시문의 수정만으로 법률 산식, 법원별 요청 조건, 사람의 최종 제출 승인 조건이 바뀌지는 않습니다. 전체 서비스 흐름은 [자동 처리 안내](ax-automation.md)를 참고하세요.
