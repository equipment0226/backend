# 프롬프트와 실행 규칙의 위치

기존 추출 지시문은 `apps/api/prompts/`에 있으며, 자동 검증과 근거 작성은 아래 모듈의 목적별 지시문·응답 스키마를 사용한다. 고객 화면에는 모델명과 내부 프롬프트를 표시하지 않는다.

| 파일 | 호출 지점 | 맡기는 작업 |
| --- | --- | --- |
| `intake.txt` | `ax_engine.analyze_intake` | 상담 원문 구간에서 인물·지역·희망 절차·팩터 종류 선택 |
| `case_evidence.txt` | `ax_engine._run_model` | 제출자료 구간에서 문서 종류·팩터 선택 |
| `legacy_review.txt` | `agent_engine.run_analysis` | 이전 검토 API의 짧은 확인 질문 |
| `manifest.json` | `prompt_registry.py` | ID·버전·호출 지점·출력 스키마·토큰 상한 등록 |
| `verification.py` | 서류·OCR·문서 검증 | 항목별 원문 인용·숫자·범위의 독립 대조; 로컬 전용 |
| `grounded_drafting.py` | 근거 문단 작성 | 사실·법률·계산에 연결된 한국어 문단; 로컬 전용 |
| `data/statement_writing_policy.json` | 진술 작성 정책 | 원본 진술서 해시·세 문단의 목적·허용/금지 표현 |
| `verification.safe_strategy_messages` | 익명 전략 검증 | 허용된 사건 수치·열거값·검증된 공개 법률로 쟁점 점검 |

직원 로그인 후 `GET /api/prompts`로 등록된 기존 추출 지시문과 SHA-256을 확인할 수 있다. 이 목록이 모든 검증·작성 지시문의 목록은 아니다. 실행 결과에는 실제 버전과 입력/정책 서명이 남는다. 프롬프트·작성 정책·근거가 바뀌면 캐시와 기존 문단의 유효성도 달라진다. manifest에 등록된 파일을 수정할 때는 버전도 함께 올린다. 변경을 과거 사건 기록에 소급해 덮어쓰지 않는다.

로컬 입력은 **system 지시문 + 사건에서 선택한 근거 구간(JSON) + 응답 스키마**다. Ollama는 `format`에 스키마를 전달한다. 외부 어댑터는 원문을 받지 않으며 허용한 익명 필드와 로컬에서 해시가 확인된 공개 법률로 입력을 새로 구성한다. 외부 검증 지시문도 서버가 구성하므로 호출자가 임의 원문 프롬프트를 전달할 수 없다. 사건 원문의 명령문을 시스템 지시로 취급하지 않고 API 키는 프롬프트에 포함하지 않는다.

다음은 프롬프트가 아니라 코드와 데이터다.

- `rulebook.py` / `data/workflow_rulebook.json`: 조건 → 필요한 문서 → 팩터 → 초안 위치를 연결하는 업무 규칙.
- `ax_engine.py`의 Pydantic 스키마와 근거 검사: 선택된 구간, 숫자, 문서 종류의 허용 범위 검증.
- `drafting.py`: 원문에서 추출한 값·미확인·충돌을 문서에 배치.
- `legal_calculator.py`: 법률 기준과 확정 입력을 사용하는 결정적 계산. LLM이 계산하지 않는다.
- `court_forms.py`: 공식 서식의 출처·버전·필드 배치.
- `ocr_engine.py`: 스캔 페이지의 문자·위치·신뢰도 추출. LLM 프롬프트를 사용하지 않는다.

진술 작성은 한국어 지시와 작은 문단별 응답으로 구성한다. 출처 ID·정확한 원문 인용·수치 대조를 별도로 검증하고 의미상 오류는 피드백을 반영해 한 번만 수정한다. 시간초과·근거 부족을 통과로 변경하지 않는다. 화면·문서·검토 사유는 한국어이며 프롬프트 수정만으로 법률 산식이나 제출 승인을 바꾸지 않는다.
