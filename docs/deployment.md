# 운영 환경을 준비할 때

현재는 로컬에서 가상 사건으로 전체 흐름을 확인할 수 있는 상태입니다. 다른 서버로 옮길 수 있도록 세 저장소에 실행·배포 파일을 준비했지만, 실제 클라우드 배포를 완료한 상태는 아닙니다.

이 문서는 운영을 맡는 사람이 어떤 데이터를 보관하고 어떤 연결을 준비해야 하는지 설명합니다. 고객과 담당자의 사용 순서는 [테스트 안내](testing.md)를 참고하면 됩니다.

## 함께 준비할 구성

| 구성 | 맡는 일 | 준비할 내용 |
| --- | --- | --- |
| 사건 서버 | 로그인, 자료 보관, 분석, 문서 작성·검토 | 사건 저장 공간, 접근 권한, 두 화면의 연결 주소 |
| 고객 화면 | 안내, 신청, 제출과 알림 | 공개 접속 주소와 사건 서버 주소 |
| 사무소 화면 | 상담, 자료 검증과 최종 검토 | 직원·변호사가 사용할 접속 주소와 권한 |
| 내부 AI·문서 판독 | 개인정보가 포함된 원문 읽기와 검토 | 내부에서 사용할 실행 환경, 한국어 판독 도구, 충분한 처리 자원 |
| 법률 자료 저장소 | 공식 본문 검색과 변경 확인 | 초기 본문 수집, 갱신 설정, 적용 기준 검토 |

원문을 읽는 AI는 내부 환경에서 사용합니다. 외부 AI의 심화 검토에는 고객 식별정보를 제외한 사건 정보만 전달합니다. 서버를 옮길 때도 이 구분을 유지해야 합니다.

## 저장해야 하는 데이터

사건 DB에는 상담, 요청 자료, 확인한 사실, 계산, 검토와 승인 기록이 들어갑니다. 업로드 원본과 작성 문서는 별도 파일로 보관하며 해당 사건과 연결합니다. DB만 남기고 파일을 잃으면 원문 대조와 작성 문서 조회가 끊길 수 있으므로 함께 보관해야 합니다.

공식 법률 본문과 변경 확인 기록도 보존해야 합니다. 서버를 새로 설치했다고 법률 자료가 자동으로 모두 준비되는 것은 아닙니다. 지식함에서 필요한 본문이 수집됐는지 확인하고 적용 기준을 검토합니다. 정기 변경 감시는 서버가 실행 중이고 갱신 기능을 켠 경우에 동작합니다. 분리 저장소의 기본 설정에서는 꺼져 있으므로 사용할 때 활성화해야 합니다.

현재 저장 방식은 서버 한 대에서 운영하는 구성을 기준으로 합니다. 여러 서버로 동시에 처리하려면 사건 저장과 파일 보관, 작업 배분을 함께 바꾸어야 합니다.

## 배포 파일을 사용할 때

분리된 각 저장소에는 자체 Dockerfile이 있습니다. 프론트 두 개에는 같은 사건 서버 주소를 지정하고, 서버에는 두 프론트 주소를 허용하도록 등록합니다. 자세한 설정과 명령은 [저장소 안내](repositories.md)와 각 README를 따릅니다.

설치를 맡는 담당자는 다음 항목도 확인해야 합니다.

- 사건 데이터는 서버 교체 후에도 남는 저장 공간에 연결합니다. 제공된 서버 배포 예시는 `/data`를 사용합니다.
- 한국어 사진·스캔 판독이 필요하면 Docker를 빌드할 때 `--build-arg ENABLE_KOREAN_OCR=1`로 판독 도구를 포함합니다. 설치만으로 실제 처리 속도가 확인된 것은 아니므로 사용할 자료로 측정해야 합니다.
- PDF 출력에는 한글 글꼴이 필요합니다. 분리 서버의 Dockerfile에는 나눔 글꼴 설치를 포함했습니다.
- 서버 상태 확인 주소는 `/api/health`, 프론트는 `/`입니다.
- 운영에서는 시연 모드를 끄고 계정·비밀번호·접근 권한을 별도로 관리합니다.

현재 로컬 코드와 프론트 빌드는 확인했지만 Docker 이미지 실행과 Railway 등 실제 클라우드 환경은 검증하지 않았습니다. 실고객 서비스를 공개하기 전에는 본인 확인, 계정 발급·회수, 비밀번호 관리, 저장 암호화와 감사 기록 접근 정책을 운영 환경에 맞게 준비해야 합니다.

## 백업과 복원

백업 도구는 사건 DB와 사건에 연결된 제출 원본·접수증·공식 작성 PDF를 함께 묶고, 보관한 내용이 원본과 같은지 검사합니다. DOCX·HTML 파일 자체는 이 백업에 포함하지 않으며, 저장된 초안 본문에서 다시 내려받을 수 있습니다. 복원할 때는 빈 폴더를 사용하며 기존 로그인 세션은 폐기합니다.

```powershell
python scripts/backup.py create .local/backups/case-backup.zip
python scripts/backup.py restore .local/backups/case-backup.zip --destination .local/restored-case-data
```

예시의 파일명과 폴더가 이미 있다면 다른 새 경로를 사용합니다. 실행 중인 사건 저장소 위에 덮어쓰지 말고 복원 결과를 확인한 뒤 별도로 실행합니다.

이 도구가 모든 운영 설정을 복사하는 것은 아닙니다. 공식 법률 본문, 법령 변경 확인 기록, AI 검토 결과 재사용 자료와 환경 키는 별도로 보관해야 합니다. 백업의 암호화와 실제 복구 연습도 운영 절차에 포함합니다.

가상 사건 한 건을 정리할 때는 계정을 포함한 전체 초기화 대신 해당 사건만 백업·삭제하는 도구를 사용할 수 있습니다. 범위와 사용법은 [테스트 안내](testing.md)에 정리했습니다.
