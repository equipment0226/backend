# 지금까지 바뀐 기능과 확인한 범위

2026년 10월 4일까지 반영한 내용을 정리했습니다. 고객이 낸 자료가 사건 정보와 작성 문서에 이어지도록 보완하고, 사건 개요에서 준비 상태와 법률상 보완 방향을 한눈에 살펴보도록 정리했습니다. 중간 결과와 수정 이력을 확인하는 방식은 유지했습니다.

## 사건 개요와 법률쟁점을 같은 근거로 연결합니다

사건 개요는 네 가지 지표와 우선 보완 항목을 중심으로 바꿨습니다. 공식 서식의 주요 항목 추출률, 현재 계산의 요건 충족, 확인된 위험 요소, 인가 확률의 산출 가능 여부를 나눠 보여 줍니다. 그래프를 누르면 상세 항목과 근거를 확인하고 해당 업무 화면으로 이동합니다. 전체 자동 처리 이력은 필요할 때 펼쳐 볼 수 있습니다.

법률쟁점도 같은 사건 자료와 공개 근거를 사용합니다. 법률 요건·쟁점·공개 판단·필요 증빙을 연결해, 단순한 빈칸 목록 대신 무엇을 확인했고 어떤 자료를 보완해야 하는지 설명합니다. 관할과 절차 단계가 다른 판례는 구분하고, 파기환송을 인가 성공으로 집계하지 않습니다. 현재 개별 인가 확률을 검증한 모델은 없으므로 추출률을 확률처럼 표시하지 않습니다.

자료나 적용 법률이 바뀌면 이전 계산·전략을 현재 결과로 표시하지 않습니다. 화면 조회는 AI를 호출하지 않으며, 사건 처리 중의 고급 검토에는 허용된 수치·분류와 검증한 공개 근거만 전달합니다. [사건 대시보드 안내](case-overview.md)에서 각 지표와 근거 연결 방식을 볼 수 있습니다.

## 상담과 서류 준비

고객의 상담 신청과 담당자의 세부 상담을 구분했습니다. 신청이 들어왔다고 곧바로 모든 자료를 요청하지 않고, 담당자가 상담을 마친 뒤 확인된 상황을 바탕으로 서류를 선정합니다.

관할 법원, 급여·사업 등 소득 형태, 거주와 가족 상황에 따라 필요한 자료를 나눕니다. 같은 거래내역도 기관·계좌·기간이 다르면 별도 요청으로 관리하고, 상황이 달라져 필요 없어진 요청은 철회할 수 있습니다. 제출 자료가 요청과 맞지 않으면 부족한 이유를 남겨 고객에게 보완을 안내합니다.

공식 서식의 작성에 필요한 주소 이력, 혼인, 연간 소득, 퇴직급여, 생활지출과 채무 경위 자료를 선정에 보완했습니다. 가상자료 29개의 확인 목적이 23개 요청묶음에 모두 연결되는지 대조했습니다. 기관·계좌가 확정되면 범위를 나누고, 같이 확인할 계약서·납부내역 등은 한 요청에 여러 원본으로 모읍니다. 법정 제출 의무와 작성 준비자료는 구분합니다.

## 여러 원본과 압축파일을 한 번에 받습니다

한 요청에 여러 파일을 추가할 수 있고 기존 자료가 새 파일 하나로 대체되지 않습니다. 연결된 모든 원본의 추출·검토를 확인한 뒤 요청을 완료합니다. 필요가 없어진 요청과 교체된 원본은 이력에 남기되 현재 계산·작성 근거에 다시 끼워 넣지 않습니다.

고객의 **한 번에 넣기**는 ZIP 안의 원문을 로컬에서 읽고 서류 종류·기관·계좌·기간에 따라 요청으로 연결합니다. 파일명은 분류의 근거로 쓰지 않습니다. 여러 요청 중 어느 곳인지 불분명하면 별도 확인 자료로 보존하고, 명의가 다른 자료는 사건의 계산 근거에 넣지 않습니다. 종류에 맞는 일반 요청이 하나뿐이면 그곳에 모으되 기관·기간의 확인이 끝났다고 표시하지 않습니다.

분류가 남은 원본은 직원·변호사가 받은 서류에서 요청 항목에 직접 연결합니다. 고객에게 같은 파일을 다시 올리게 하지 않고, 연결 이유와 이력을 남긴 뒤 그 범위의 원문·추출값을 검토합니다. 연결 자체를 검토 완료로 처리하지 않습니다.

화면에는 파일별 진행과 연결 결과를 보여 줍니다. 창을 닫아도 접수는 이어지고 같은 작업을 다시 조회할 수 있습니다. 압축파일은 50MB, 원본은 최대 100개·각 10MB·합계 100MB까지 받습니다. 알집에서 만든 표준 ZIP도 사용할 수 있으며 ALZ·EGG 전용 형식은 ZIP으로 다시 압축해야 합니다.

연습용 다운로드는 제출할 PDF만 담았습니다. 이하늘과 박지우의 이름에 맞는 묶음을 선택하고, 검산용 정답이나 가상의 법률 판단은 제출자료에서 제외합니다.

## 고객 화면과 사무소 화면

고객 페이지는 메인, 개인회생 소개, 내 사건, Q&A, 후기와 상담 안내로 나눴습니다. 따뜻한 이미지와 간결한 설명으로 진입 화면을 구성하고, 로그인·알림과 사건 진행 조회를 연결했습니다. AI 상담에서 담당자 연결을 요청하면 사무소가 확인할 요청이 남습니다.

직원·변호사 화면은 사건 개요에서 자동 처리 진행 상황을 보고 상담, 자료 검증, 계산, 문서 작성 화면으로 이어지도록 했습니다. 새 알림은 미확인 개수와 내용으로 표시합니다. 문서 요청은 내부 데이터 형식 대신 읽을 수 있는 카드로 보여주며, 고객에게 내부 사건 코드가 불필요하게 드러나는 표시도 줄였습니다.

## 급여명세서 외 서류도 함께 읽도록 보완

| 이전에 문제가 되던 상황 | 지금 처리하는 방식 |
| --- | --- |
| ‘급여외 소득 없음’을 무직으로 해석 | 급여·재직 자료와 문장의 대상을 함께 확인합니다. |
| 연간 소득이나 연금 기준소득을 월 실수령액으로 사용 | 자료의 목적, 금액의 종류, 대상 기간을 구분합니다. |
| 긴 원문이나 표의 뒷부분이 빠짐 | 원문 전체와 페이지를 보관하고, 분석에 쓰는 분량은 별도로 나눕니다. |
| 같은 예금이 여러 자료에 나와 중복 합산 | 계좌와 기준일을 맞춰 같은 잔액을 한 번만 반영합니다. |
| 한 파일에 있는 여러 채권자의 금액이 섞임 | 채권자·대출·페이지별 내용을 나누어 정리합니다. |
| AI가 늦거나 응답하지 않아 문서가 비어 버림 | 확인한 값과 기존 문서는 보존합니다. 원문 전체 대조가 끝나기 전에는 새 작성을 기다리며, 완료 후의 미확정 판단은 보완 항목으로 남깁니다. |
| 예금 금액을 생활비처럼 설명 | 문장의 금액뿐 아니라 그 금액이 무엇을 뜻하는지도 원문과 대조합니다. |

읽은 값에는 원문 위치와 인용을 연결합니다. 따라서 담당자는 “이 값은 어느 서류에서 왔는가”를 확인하며 수정할 수 있습니다. 흐릿한 문자나 서로 다른 값은 확정하지 않고 검토 목록에 남깁니다.

## 받은 서류와 추출 내용을 한 번에 검토합니다

자료 검증 화면 위쪽에서 요청한 서류, 받은 서류, 검토가 끝난 서류를 먼저 확인합니다. 각 서류의 ‘추출내용 보기’를 열면 원본과 읽은 값이 함께 나옵니다. 잘못 읽은 부분만 수정하거나 제외하고, 해당 서류의 검토 완료를 한 번 누르면 나머지 값도 함께 확인됩니다.

서류마다 읽기 대기·진행·완료·재확인 상태를 표시합니다. 아직 읽지 못한 페이지나 항목이 있으면 검토 완료와 다음 단계 진행을 기다립니다. 모든 필요한 자료를 확인한 뒤에도 AI의 원문 대조가 일부만 끝났거나 시간 초과가 발생하면 새 문서를 만들지 않습니다. 기존 문서와 수정 이력은 그대로 남습니다.

담당자가 고친 값은 원문과 별도로 보관하고 누가 어떤 근거로 수정했는지 연결합니다. 그 값이 계산과 문서 작성에도 이어지므로, 나중에 다시 자료를 읽었다는 이유로 수정 내용이 사라지지 않습니다.

## 계산과 1차 문서가 자동으로 이어집니다

필요한 자료의 제출·검토가 끝나면 확인된 값을 계산과 쟁점 검토에 연결하고 1차 문서를 작성합니다. 진술서는 상담 메모를 그대로 붙이지 않고 채무가 생긴 경위, 상환이 어려워진 사정, 앞으로의 변제 여건을 나눠 설명하도록 구성했습니다.

근거 없는 문장이나 금액의 의미가 다른 문장은 재검토합니다. AI 작성이 검증을 통과하지 못하면 확인된 사실을 담은 검토용 요약을 남깁니다. 이 요약을 AI 검토 완료 문서로 표시하지는 않습니다. 법률상 인정 여부, 개인정보와 서명 등 미확정 항목은 담당자가 보완해야 합니다.

법원 서식 화면은 작성된 문서를 먼저, 원본 서식을 아래에 모아 보여줍니다. PDF는 수임번호와 서류명으로 내려받고, 한글 글꼴과 작성 칸 배치를 조정했습니다. 긴 내용은 별지로 이어지며 줄 겹침과 점선 위의 글자 배치도 수정했습니다.

## 법률 자료와 이후 사건에 남는 정보

공식 법령·법원 자료의 본문을 저장하고 읽을 수 있게 했습니다. 변경 감시는 본문과 시행 시점을 비교하고, 지원하는 범위의 변경을 적용하거나 추가 검토 대상으로 남깁니다. 새 자료가 수집됐다는 이유만으로 검토하지 않은 법률 판단까지 자동 확정하지 않습니다.

작성 문서와 보완·법원 결과를 따로 보관해, 확인된 사례를 이후 검색과 작성에 참고할 수 있도록 했습니다. 아직 개별 사건의 인가 확률을 예측하는 검증된 모델은 없습니다. 유사한 종결 사건이 충분하지 않으면 결과 비율도 표시하지 않습니다.

계좌 두 개의 기관·번호·잔액과 보험회사·증권번호도 원본 재산목록의 상세 칸에 연결했습니다. 길어서 들어가지 않는 값은 ‘별지’ 표시와 함께 전체 내용을 보존합니다. 소득증명서의 소득 확인 시작일은 해당 급여를 증명하는 기간에서 가져오며, 입사일을 대신 넣지 않습니다. 서명과 발급자 확인, 미확정 법률 판단은 자료에서 읽은 사실과 구분합니다.

## 현재 연습 사건과 자료

앞선 작업에서 박지우 가상 사건을 준비했으며, 마지막 요청에 따라 기존 사건을 모두 백업 후 비웠습니다. 로그인 계정과 법률·서식 자료는 유지합니다. 사용자가 이하늘 사건을 직접 신청하도록 신규 사건을 미리 만들거나 제출·검토를 대신 진행하지 않았습니다.

연습자료는 주민등록·가족관계, 12개월 급여, 재직·세금·보험, 두 계좌의 거래내역, 세 채권자의 채무자료, 임대차·퇴직금, 생활비와 채무 경위를 함께 담았습니다. 공식 서식의 어떤 칸을 어떤 자료로 채우는지 대응표도 들어 있습니다. 법률 판단 예시는 원본 증빙과 분리했으며 자동으로 사건에 적용하지 않습니다.

[테스트 안내](testing.md)에서 접속 주소와 계정, 제출할 자료, 확인할 순서를 볼 수 있습니다. 검사 기록의 위치는 [실행 환경과 확인 기록](runtime-analysis.md)에 정리했습니다. 초기 기획의 요구 목록은 [기존 요구 기록](../data/requirements.json)에 보존하며 현재 기능의 완성률로 사용하지 않습니다.
