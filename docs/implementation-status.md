# 현재 구현과 기존 요구 추적

현행 동작은 [구조](architecture.md), [자동 처리와 검증](ax-automation.md), [문서 목록](README.md)에 설명합니다. 실행·화면·진행 이력의 정본은 `apps/api/workflow_contract.py`입니다.

현재 흐름은 법원별 서류 선정·고객 보완·원문 검증·구조화 자료·법률계산·익명 전략 검증·1차 문서 작성·AI 문서 검토·담당자 보완·변호사 최종 승인·제출 기록입니다. 서류 제출·검토가 완료되면 미확정 항목도 공란·보완 목록으로 구분해 1차 작성까지 자동 진행합니다. 수정본은 AI로 다시 대조하며, 최종 승인 후 외부 제출 접수증으로 내부 기록을 남깁니다. 실제 법원 전송이나 인가를 자동 처리한 것으로 표시하지 않습니다.

이 문서의 추적 표는 초기 요구 265개의 ID·수용조건·출처를 보존하기 위한 목록입니다. 기존 분류는 당시 검토 범위이며 최신 자동화 기능의 전체 목록이나 제품 완성률이 아닙니다. 초기 기획 묶음은 정리했지만 `data/requirements.json`, `data/registry.json`, `data/reference_evidence/imported_source_inventory.json`의 출처는 보존합니다.

2026-10-04 문서 추출 보완: 신분·가족·소득·재직·보험·연금·채무·계좌·재산·거주·경위 자료를 의미·단위·기간·기관·계좌·대출별로 구분합니다. 기존/새 가상자료 각15종에서 119/123개 관측을 관련7종 PDF의 작성 칸과 근거별지에 보존하는 검사를 수행했습니다. 예금 중복 합산, 한 PDF의 여러 채권자 혼합, 연소득을 월소득으로 읽는 오류를 방지합니다. AI 검증 지연이 확인된 원문 값을 지우지 않으며, 본문 금액의 용도가 인용과 다르면 재작성하거나 사실 요약 초안으로 전환해 검토 요청합니다. 이 요약은 AI 검증 완료 본문이 아닙니다.

## 검증 근거

`python scripts/run_tests.py`는 `.work/tests`의 격리된 저장소에서 회귀시험을 수행하고 `reports/test-results.json`을 갱신합니다. 모델 대역 시험과 실제 호출을 구분합니다. 실제 원문/익명 모델 호출은 `reports/ax-live-verification.json`, 최신 진술 작성은 `reports/statement-authoring-live.json`의 상태·실패 이유를 확인합니다. 최신 실제 호출을 이전 버전의 성공으로 대체하지 않습니다.

법률계산 지원 범위는 [계산 문서](legal-calculation.md), PDF 원본·글꼴·매핑 범위는 [서식 문서](court-forms.md), 공식 원문 갱신과 비용 한도는 [자동화 문서](ax-automation.md)를 따릅니다. 개별 인가 예측 모델은 없으며 유사 종결 표본이 부족하면 관측 비율도 표시하지 않습니다.

최신 원문→항목→PDF/DOCX/HTML 검사는 `reports/ocr-audit/`에서 확인합니다. 실제 로컬 작성의 금액 의미 검사 보류와 렌더링 검사 통과는 별개입니다. 스캔 식별자의 O/0 충돌과 미확정 법률 판단은 검토 대상으로 유지하며, 실제 모든 기관 서식에서의 정확도나 제출 가능성을 주장하지 않습니다. 새 수동 테스트는 [이하늘 사례 안내](testing.md), 분리 배포는 [저장소 안내](repositories.md)를 따릅니다.

최신 회귀시험의 통과·실패·건너뜀 수와 검증 항목은 `reports/test-results.json`에서 확인합니다. AI 검토→보완→최종 승인→접수 기록의 격리 화면 시험은 `reports/browser-document-workflow.json`에 있습니다. 시험 결과는 법률 정확도나 현장 인수의 지표가 아닙니다.
