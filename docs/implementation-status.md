# 지금까지 바뀐 기능과 확인한 범위

2026년 10월 4일까지 반영한 내용을 정리했습니다. 이번 작업의 중심은 고객이 낸 자료가 사건 정보와 작성 문서에 제대로 이어지도록 보완하는 것이었습니다. 화면에서 중간 결과와 수정 이력을 확인하는 방식은 유지했습니다.

## 상담과 서류 준비

고객의 상담 신청과 담당자의 세부 상담을 구분했습니다. 신청이 들어왔다고 곧바로 모든 자료를 요청하지 않고, 담당자가 상담을 마친 뒤 확인된 상황을 바탕으로 서류를 선정합니다.

관할 법원, 급여·사업 등 소득 형태, 거주와 가족 상황에 따라 필요한 자료를 나눕니다. 같은 거래내역도 기관·계좌·기간이 다르면 별도 요청으로 관리하고, 상황이 달라져 필요 없어진 요청은 철회할 수 있습니다. 제출 자료가 요청과 맞지 않으면 부족한 이유를 남겨 고객에게 보완을 안내합니다.

## 고객 화면과 사무소 화면

고객 페이지는 메인, 개인회생 소개, 내 사건, Q&A, 후기와 상담 안내로 나눴습니다. 따뜻한 이미지와 간결한 설명으로 진입 화면을 구성하고, 로그인·알림과 사건 진행 조회를 연결했습니다. AI 상담에서 담당자 연결을 요청하면 사무소가 확인할 요청이 남습니다.

직원·변호사 화면은 사건 개요에서 자동 처리 진행 상황을 보고 상담, 자료 검증, 계산, 문서 작성 화면으로 이어지도록 했습니다. 새 알림은 미확인 개수와 내용으로 표시합니다. 문서 요청은 내부 데이터 형식 대신 읽을 수 있는 카드로 보여주며, 고객에게 내부 사건 코드가 불필요하게 드러나는 표시도 줄였습니다.

## 급여명세서 외 서류도 함께 읽도록 보완

| 이전에 문제가 되던 상황 | 지금 처리하는 방식 |
| --- | --- |
| ‘급여외 소득 없음’을 무직으로 해석 | 급여·재직 자료와 문장의 대상을 함께 확인합니다. |
| 연간 소득이나 연금 기준소득을 월 실수령액으로 사용 | 자료의 목적, 금액의 종류, 대상 기간을 구분합니다. |
| 긴 원문이나 표의 뒷부분이 빠짐 | 원문 전체와 페이지를 보관하고, 분석에 쓰는 분량은 별도로 나눕니다. |
| 같은 예금이 여러 자료에 나와 중복 합산 | 계좌와 기준일을 맞춰 같은 잔액을 한 번만 반영합니다. |
| 한 파일에 있는 여러 채권자의 금액이 섞임 | 채권자·대출·페이지별 내용을 나누어 정리합니다. |
| AI가 늦거나 응답하지 않아 문서가 비어 버림 | 원문에서 확인한 값은 보존하고, 불확실한 부분만 보완 대상으로 남깁니다. |
| 예금 금액을 생활비처럼 설명 | 문장의 금액뿐 아니라 그 금액이 무엇을 뜻하는지도 원문과 대조합니다. |

읽은 값에는 원문 위치와 인용을 연결합니다. 따라서 담당자는 “이 값은 어느 서류에서 왔는가”를 확인하며 수정할 수 있습니다. 흐릿한 문자나 서로 다른 값은 확정하지 않고 검토 목록에 남깁니다.

## 계산과 1차 문서가 자동으로 이어집니다

필요한 자료의 제출·검토가 끝나면 확인된 값을 계산과 쟁점 검토에 연결하고 1차 문서를 작성합니다. 진술서는 상담 메모를 그대로 붙이지 않고 채무가 생긴 경위, 상환이 어려워진 사정, 앞으로의 변제 여건을 나눠 설명하도록 구성했습니다.

근거 없는 문장이나 금액의 의미가 다른 문장은 재검토합니다. AI 작성이 검증을 통과하지 못하면 확인된 사실을 담은 검토용 요약을 남깁니다. 이 요약을 AI 검토 완료 문서로 표시하지는 않습니다. 법률상 인정 여부, 개인정보와 서명 등 미확정 항목은 담당자가 보완해야 합니다.

법원 서식 화면은 작성된 문서를 먼저, 원본 서식을 아래에 모아 보여줍니다. PDF는 수임번호와 서류명으로 내려받고, 한글 글꼴과 작성 칸 배치를 조정했습니다. 긴 내용은 별지로 이어지며 줄 겹침과 점선 위의 글자 배치도 수정했습니다.

## 법률 자료와 이후 사건에 남는 정보

공식 법령·법원 자료의 본문을 저장하고 읽을 수 있게 했습니다. 변경 감시는 본문과 시행 시점을 비교하고, 지원하는 범위의 변경을 적용하거나 추가 검토 대상으로 남깁니다. 새 자료가 수집됐다는 이유만으로 검토하지 않은 법률 판단까지 자동 확정하지 않습니다.

작성 문서와 보완·법원 결과를 따로 보관해, 확인된 사례를 이후 검색과 작성에 참고할 수 있도록 했습니다. 아직 개별 사건의 인가 확률을 예측하는 검증된 모델은 없습니다. 유사한 종결 사건이 충분하지 않으면 결과 비율도 표시하지 않습니다.

숫자는 이번 가상 사례와 검사 범위의 결과입니다. 모든 기관의 실제 서류에서 같은 정확도를 확인한 결과는 아닙니다. 실제 AI 작성에서 의미 검증이 보류된 사례도 있었으며, 이때 사실 요약과 보완 목록이 남는 동작을 확인했습니다.

## 다시 신청해 볼 수 있는 상태

이전 가상 사건은 백업 후 삭제했고 세 역할의 계정은 유지했습니다. 초기화 직후 사건은 0건이며, 새로운 ‘이하늘’ 상담 예시와 연습자료를 준비했습니다. 예시를 불러오는 것만으로 사건이 만들어지지는 않습니다. 고객이 직접 동의하고 신청해야 시작합니다.

[테스트 안내](testing.md)에서 접속 주소와 계정, 제출할 자료, 확인할 순서를 볼 수 있습니다. 검사 기록의 위치는 [실행 환경과 확인 기록](runtime-analysis.md)에 정리했습니다. 초기 기획의 요구 목록은 [기존 요구 기록](../data/requirements.json)에 보존하며 현재 기능의 완성률로 사용하지 않습니다.
