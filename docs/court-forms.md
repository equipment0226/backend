# 공식 법원 서식에 사건 내용을 작성하는 기능

공식 PDF의 선·표·안내문을 유지하면서 사건 자료에서 확인한 내용을 해당 칸에 배치합니다. 직원은 원본 양식과 작성본을 함께 내려받아 비교하고, 작성값의 출처와 빈칸·넘침·보완 사유를 확인할 수 있습니다.

자동 작성의 결과는 **담당자가 검토할 1차 초안**입니다. 자료가 확인된 부분은 채우고, 미확정 금액이나 법률 판단은 공란 또는 검토가 필요한 제안으로 구분합니다. 서명·날인·동의나 사실 확인 선언을 자동으로 대신하지 않습니다.

법원 서식 화면의 작성된 PDF 카드에서 **미리보기**를 누르면 저장된 문서를 바로 펼쳐 볼 수 있습니다. 브라우저의 쪽 이동·확대 기능으로 본문과 별지 전체를 살펴보고, 필요한 문서는 `수임번호_서류명.pdf`로 내려받습니다. 작성 항목과 AI 검토 결과는 기존 **작성 내용·AI 검토 확인**에서 이어서 확인합니다. 공식 빈 서식은 화면 아래에 따로 유지합니다.

미리보기는 현재 로그인 계정의 열람 권한을 확인한 뒤 문서를 가져오며 외부 문서 뷰어에 보내지 않습니다. 뒤로가기나 닫기를 누르면 서식 목록의 기존 위치로 돌아갑니다. 불러오는 중에는 진행 안내가 보이고, 파일을 찾지 못하거나 연결에 문제가 생기면 재시도 방법을 안내합니다. 이전 작성본도 이력에서 열어 비교할 수 있으며, 미리보기를 열었다고 검토나 승인이 완료되는 것은 아닙니다.

## 작성할 수 있는 문서

| 서식 | 주로 반영하는 내용 | 확인할 사항 |
| --- | --- | --- |
| 개인회생절차 개시신청서 | 인적 사항, 관할, 확인된 신청 관련 값 | 연락처·식별정보·월 변제예정액 등 부족 항목 |
| 개인회생채권자목록 | 채권자별 원금·이자·채무 합계와 근거 | 담보·다툼·별도 부속표, 채권자 동일성 |
| 재산목록 | 계좌 잔액, 보증금, 확인된 보험·재산 정보 | 법률상 평가·공제·면제 여부 |
| 수입 및 지출에 관한 목록 | 월소득, 원문에 표시된 기간, 생활비와 가구 정보 | 실제 지출과 법률상 인정생계비의 차이 |
| 진술서 | 채무 발생 경위, 지급 곤란 사정, 향후 변제의 근거 | 문장별 출처와 금액의 의미 |
| 가용소득만으로 변제하는 변제계획안 | 검증된 계산에 따른 변제 내용과 채권자 배분 | 해당 계획 유형의 적용 가능성, 기간·비용·납입일 |
| 급여소득자 소득증명서 | 근무처, 담당 업무, 확인된 근무기간과 소득 | 사용자의 확인이 필요한 부분 |

공통 7종을 등록된 15개 법원에 연결합니다. 15개 법원별로 서로 다른 서식을 모두 마련한 것은 아닙니다. 부산회생법원의 별도 자료제출목록도 보관·작성 대상으로 제공합니다. 관할별 추가 요구와 접수 당시 공지는 최종 검토에서 확인합니다.

원본 작성례의 이름과 금액을 실제 사건에 가져오지 않습니다. 작성례 페이지는 생성 대상에서 제외하며, 담보부 채권·다툼 있는 채권 등에 필요한 별도 부속표는 추가 검토 대상으로 남깁니다.

## 확인된 사실과 미확정 판단의 구분

원문에서 확인한 월급·계좌 잔액·채권 원금과 이자는 계산 승인을 기다리는 동안에도 검토용 초안에 반영할 수 있습니다. 같은 계좌의 중복 합산이나 서로 다른 대출의 혼합을 막기 위해 작성 시 원문과 집계 근거를 다시 대조합니다.

생계비 인정인원, 추가 생계비, 면제재산과 비용은 법률 판단이 필요합니다. 원문 금액이 갖춰지면 변제기간을 기본 36개월로 두고, 아직 확인하지 못한 조건을 가정으로 명시한 검토용 계산을 문서에 연결할 수 있습니다. 월변제액·전체 변제액·청산가치와 배분표를 채우되, 문서 전체에 가정 계산 표시와 남은 확인 사항을 함께 남깁니다. 이 숫자를 법률상 인정이 끝난 결과로 표시하지 않습니다.

승인 계산 또는 자동 검증을 통과한 유효한 계산은 기존의 검증된 계산 경로로 사용합니다. 가정 계산은 현재 원문·정책·입력·결과·가정을 재현 대조하는 별도 경로를 거치며 승인되지 않은 상태를 유지합니다. 확인된 사실과 계산 결과를 직원 입력으로 덮어써 검토를 우회할 수 없으며, 수정할 필요가 있으면 근거와 입력을 보완해 새 버전을 만듭니다.

## 근거별로 작성하는 진술서

기본 진술은 채무 발생 경위, 지급 곤란 사정, 향후 변제의 근거를 세 문단으로 정리합니다. 상세 상담의 당사자 설명과 증빙을 구분하고, 관련 법률·판례와 검증된 사례 자료를 참고하되 그 사례의 사실을 현재 사건에 옮기지 않습니다. 상담 메모의 “가상 사례”, “실제 사건 아님” 같은 안내문도 사건의 경위로 복사하지 않습니다.

작성 후에는 인용과 숫자가 원문에 있는지뿐 아니라 금액의 뜻도 확인합니다. 예금 240만원을 생활비 240만원으로 바꾸거나 연간 총급여를 월 실수령액으로 쓰는 문장은 통과시키지 않습니다. 의미상 오류에는 한 차례 수정을 시도하고, 검토 실패나 사용 불가 상태를 성공으로 바꾸지 않습니다.

전체 자동 진행에서는 문장 작성을 끝내지 못해도 원문에서 확인한 채무·소득·생활비 등의 사실을 정리한 검토용 본문을 남길 수 있습니다. 이 본문은 설득력 있는 최종 진술의 완성이나 AI 의미 검토 통과를 뜻하지 않습니다. 채무 경위 등 부족한 설명은 담당자가 보완합니다. 진술서만 별도로 새로 작성하는 화면의 자동 작성은 검증에 실패하면 보류하며, 직원이 명시적으로 직접 입력한 내용도 별도 검토가 필요합니다.

## 원본 양식의 배치와 별지

작성값은 원본 행의 기준선에 맞추고, 숫자는 읽기 쉬운 방향으로 정렬합니다. 원본에 어울리는 명조·바탕 계열 글꼴을 사용하며 칸에 맞춰 크기를 조정합니다. 너무 긴 값은 잘라내지 않고 넘침을 표시한 뒤 별지에 보존합니다.

별지에는 작성값, 문서명, 쪽·줄, 원문 인용과 미확인 항목이 이어집니다. 인용의 줄바꿈과 페이지 나눔을 따로 계산해 다음 항목과 겹치지 않게 합니다. 채권자가 본표의 네 칸보다 많아도 전체 목록을 남깁니다. 승인된 변제 계산이 연결되면 채권자별 배분과 모든 회차의 입금·보수·변제액도 별지에서 확인할 수 있습니다. 납입 시작일을 입력한 경우에만 계획 날짜를 표시하며 법원의 확정 납입일로 표현하지 않습니다.

생성된 과거 PDF는 나중에 덮어쓰지 않습니다. 자료·서식·배치가 바뀌면 새 문서 버전을 만들고 다시 검토합니다. 원본과 작성본이 나중에 변경되지 않았는지 확인할 기록도 이력에 보관합니다. 검토 대조표는 실제 제출 전에 분리·정리할 필요가 있습니다.

## 실제 검증 범위와 남은 한계

각 15종으로 구성된 두 가상사건에서 7종 PDF를 각각 생성했습니다. 첫 사건의 원문에서 확인한 항목 119개, 두 번째 사건의 123개가 인용과 함께 모두 보존됐고, 채운 값이 원래 칸 또는 명시된 넘침 별지에 있는지 대조했습니다. 편집용 문서에도 주요 금액과 진술 본문이 남는지 확인했습니다.

두 번째 사건의 최종 PDF 35쪽은 시각 검토도 수행했습니다. 채권 산정근거가 점선과 겹치던 문제와 별지 인용의 여러 줄이 겹치던 문제를 수정한 뒤, 변경된 다섯 쪽을 다시 확인했습니다. 나머지 30쪽은 앞서 검토한 이미지와 동일했습니다.

이 검증은 내용 보존과 배치 확인입니다. 당시 의미 검토가 완료되지 않은 진술은 확인된 사실 요약으로 남았으며, 법원 제출 승인이나 AI 작성 품질의 완성을 입증하지 않습니다. 현재 다음 항목은 별도로 확인해야 합니다.

- 긴 은행명·계좌는 별지에 모두 있지만 원래 칸은 비어 있고 별지 참조 표시가 없는 경우가 있습니다.
- 입사일·거주시작일은 확인된 날짜의 해당 칸에 연결했습니다. 연·월만 확인된 자료에 임의로 1일을 더하지 않습니다.
- 변제액·보수·배분액은 현재 원문과 명시한 가정으로 계산 가능한 경우 검토용 초안에 담습니다. 해당 서류를 완성된 제출본으로 취급하면 안 됩니다.
- 일부 원본의 이어지는 쪽에는 초안 표시가 눈에 보이지 않을 수 있습니다. 문서 전체의 검토 상태로 구분해야 합니다.
- 별지는 원문을 보존해 분량이 많고, 일부 넘침 경고에는 내부 항목명이 남아 있습니다.

로컬 검사 기록: 첫 7종 작성본 대조: `reports/ocr-audit/fresh_start-generated-documents.json`, 두 번째 7종 작성본 대조: `reports/ocr-audit/ocr_retest-generated-documents.json`, 최종 시각 검토와 한계: `reports/ocr-audit/generated-visual-review.json`.

## 현재 사건의 실제 추출값과 다시 대조했습니다

박지우 가상사건의 기존 7종 PDF는 등록된 171칸 중 91칸에 값이 있었고, 기재값이 출력 과정에서 사라진 경우는 없었습니다. 다만 원문에서 읽은 내용이 별지에만 있고 실제 본문 칸에 연결되지 않은 영역이 있었습니다.

입사일·학력·혼인이력·거주시작, 반복 신청인명·직장명, 채권자 연락처·잔액 기준일·원문 산정근거를 추가로 연결했습니다. 본문 연결만 보완한 비교본은 204칸 중 114칸이 채워졌고, 같은 자료에 36개월 가정 계산을 연결한 비교본은 158칸이 채워졌습니다. 남은 등록 필수 칸은 변제 시작·종료 날짜 6칸입니다. 서명·동의와 원본의 모든 선택란까지 자동 완성했다는 의미는 아닙니다.

기존 작성본과 사건 상태는 그대로 두고 별도 비교본을 만들었습니다. [HTML 사건 자료집](review-files.md)에서 기존 기재값, 공란 사유, 본문 보완과 계산이 반영된 작성본을 나란히 확인할 수 있습니다.

## 원본·운영 참고

공식 원본은 2026년 10월 3일 [대한민국 법원 양식 목록](https://www.scourt.go.kr/nm/minwon/doc/DocListAction.work?min_gubun=l&pageIndex=1)에서 수집한 PDF 8개와 HWP 9개입니다. [출처 목록](../data/court_forms/sources.json)에 원본 URL·수집일·파일 변경 여부를 확인할 기록을 보관합니다. 서식 자체의 시행일과 수집일은 다르며, 현재 접수 시점의 효력을 이 수집 기록만으로 확정하지 않습니다.

HWP는 원본 내려받기를 지원하며 자동 편집은 포함하지 않습니다. 가용소득 전용 변제계획안의 원본 선택 문구는 실제 계산과 적용 범위를 별도로 검토합니다. 재산 매각을 재원으로 삼는 계획이나 지원하지 않는 소득 유형을 해당 서식으로 자동 통과시키지 않습니다.

작성·배치 검증은 [서식 처리](../apps/api/court_forms.py)와 [출력 문서 대조](../apps/api/auto_documents.py)가 담당합니다. 재검증은 python -m unittest tests.test_court_forms tests.test_court_forms_typography tests.test_auto_documents_review로 실행합니다. 이후 업무는 [보완·최종 승인·제출 처리](document-workflow.md)를 따릅니다.
