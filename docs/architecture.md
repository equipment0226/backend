# 사건 처리 구조

고객·직원·변호사 화면은 하나의 FastAPI와 SQLite 사건 원장을 공유합니다. 제출 자료와 검증 결과가 같은 사건 버전으로 연결됩니다. 자료 제출·검토 완료 후 1차 작성·AI 검토까지 자동 진행하고, 미확정 항목은 문서와 함께 담당자에게 넘깁니다. 보완 후 변호사 최종 승인을 받아 외부 접수 사실을 기록합니다.

## 단계 계약

[workflow_contract.py](../apps/api/workflow_contract.py)의 `STAGES`가 실행·화면 진행·이력의 공통 계약입니다.

| 단계 | 입력 | 출력 | 다음 진행 조건 / 실패 처리 |
| --- | --- | --- | --- |
| collection | 상담·관할 기준 | 기관·계좌·기간별 요청·제출 이력 | 현재 기준의 모든 유효 요청 충족 / 보완 요청 |
| validation | 제출 원문·요청 범위 | 인물·종류·기간·발급옵션 확인 | 실제 원문과 요청 일치 / 고객 재요청 |
| ocr | 검증 자료·추출 후보 | 근거가 연결된 구조화 값 | 추출값·계산 입력의 독립 원문 대조 / 미확정 값을 공란·보완 목록으로 작성 |
| analysis | 구조화 값·현행 근거·확인된 결과 | 계산·쟁점·보완 전략 | 확인된 입력의 계산·익명 전략 검증 / 미확정 판단을 1차 작성본에 연결 |
| draft | 사건 사실·관련 법령/판례·계산 | 근거별 문단·불변 문서 버전 | 출처·금액 대조·필수 사실 확보 / 추가 사실 요청·작성 검토 |
| review | 문서·원문·계산·공식 서식 | 검증 범위가 명시된 작성본 | 본문·작성값·등록된 원본 선택 조항 확인 / 새 버전 작성·검토 |
| human_review | 작성본·AI 검토·미확정 판단 | 보완 문서·변호사 최종 승인 | 사실·판단 보완과 수정본 AI 재검토 / 추가 증빙·새 버전 작성 |
| submission | 현재 승인 문서·접수 근거 | 내부 제출 기록 | 승인본·접수증 일치 / 변경 시 재승인·접수 근거 보완 |

[triz_backend의 단계 정본](https://github.com/equipment0226/triz_backend/blob/main/docs/STAGES.md)과 [학습 구조 설명](https://github.com/equipment0226/triz_backend/blob/main/docs/LEARNING.md)을 참고해 입출력·검증·실패 경로를 한곳에 정의했습니다. 이 시스템은 회생 업무의 여덟 단계이며 TRIZ의 전체 파이프라인을 실행하지 않습니다.

체크포인트에는 단계·입력 리비전·완료 단계·현재 통과 조건·사유 코드·법률 버전을 기록합니다. 재개는 오케스트레이터에 다시 진입해 현재 증빙과 해시가 맞는 중간 결과를 재사용하는 방식입니다. 중단된 코드의 특정 줄부터 실행하는 기능은 아닙니다. 자료·법률 버전이 바뀐 결과는 재검증합니다.

## 근거 기반 작성

상담은 당사자 진술, 검증 서류는 증거, 계산은 파생값으로 구분합니다. 진술서는 채무 발생 경위·지급 곤란 사정·향후 변제계획을 각각 작성합니다. 상담의 테스트 안내·편집 지시를 제출용 문장으로 복사하지 않습니다. 관련 공식 근거는 제한된 수만 검색하고 동일 사무소·관할의 검증된 결과 예시는 익명 구조만 참조합니다.

각 문단은 출처 ID와 정확한 인용을 반환하고 독립 검증을 거칩니다. 근거 없는 숫자, 과거 사례의 사실을 현재 사건에 붙인 문장, 인가 보장은 허용하지 않습니다. 의미상 검증 실패에는 한 번의 피드백 수정을 허용합니다. 시간초과·사용 불가·불완전한 응답은 자동 재시도로 덮지 않고 보류합니다. 수동 진술 입력은 직원 작성/검토 필요 상태로 구분합니다.

문단 재사용은 작성 버전·정책·현재 증빙·상담·계산·법률 버전을 포함한 서명에 묶입니다. 오래된 한 문장 초안이나 상담 메모를 대체 내용으로 사용하지 않습니다. 진술 검증과 실제 PDF 검증은 별개이며 서명·동의는 자동 완료하지 않습니다.

## 데이터와 경계

외부 모델 호출 중 SQLite 쓰기 트랜잭션을 유지하지 않습니다. 별도 사건 사본에서 처리한 뒤 원래 사건 버전과 적용 법률을 비교해 저장합니다. 사건 변경 이력·구조화 자료·문서 버전·법원 결과는 같은 변경 트랜잭션으로 기록합니다. 이전 PDF와 검토 기록은 불변으로 보존합니다.

고객 원문·실명·계좌·상담 자유문장은 로컬에서 처리합니다. 외부에는 허용한 수치·열거값으로 재구성한 익명 정보와 로컬에서 출처·해시를 확인한 공개 법률 본문만 보냅니다. 캐시도 이 익명 경계를 통과한 결과만 보관합니다.

공식 원문의 저장은 사건 적용 승인과 구분합니다. 법령 감시는 본문·시행일·기존 검토 문언을 대조하고 지원하는 한도·기간의 수치 변경만 제한적으로 반영합니다. 의미 변경·추가 조건·미확보 법원 기준은 검토가 필요합니다.

실제 결과 축적은 후속 검색·작성의 근거를 개선하며 모델 가중치를 자동 재학습하지 않습니다. 합성·미검증·파기환송·면책을 신청 인가 표본으로 세지 않습니다. 유사 종결 표본이 부족하면 관측 비율은 없으며, 개별 인가 예측은 보정된 모델과 독립 평가가 없어 보류합니다.
