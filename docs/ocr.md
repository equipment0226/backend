# 스캔과 PDF에서 원문을 읽는 기능

고객이 올린 PDF와 사진에서 글자·숫자·표를 읽고, 그 내용이 원본의 어느 위치에 있었는지 함께 남깁니다. 문자로 저장된 PDF는 원래 본문을 가져오고, 사진으로 된 페이지는 글자를 판독합니다. 한 파일 안에 두 방식이 섞여 있어도 페이지별로 처리합니다.

**고객 서류의 원문은 외부로 전송하지 않고 로컬에서 판독합니다.** 읽어 낸 결과는 이후 [항목·단위·기간 대조](document-extraction.md)에 전달합니다. 글자를 읽는 단계와 “이 금액이 월급인지, 잔액인지”를 해석하는 단계는 구분합니다.

## 원본을 보존하면서 판독

본문을 정해진 글자 수에서 잘라 저장하지 않습니다. 페이지별 본문, 판독 원문, 줄의 위치와 읽기 상태를 보존합니다. 원래 문자가 들어 있는 PDF에는 임의의 판독 신뢰도를 붙이지 않습니다.

표는 같은 높이에 있는 항목과 금액을 위치에 따라 왼쪽부터 연결합니다. 이미지가 여러 조각으로 나뉜 스캔도 확인합니다. 원래 문자와 이미지가 함께 있는 페이지에서는 두 내용을 각각 남기며, 같은 위치의 내용이 다르면 한쪽으로 덮어쓰지 않고 대조할 부분으로 표시합니다. 스캔 판독이 실패해도 이미 읽을 수 있었던 원래 PDF 본문은 유지합니다.

직원은 추출값의 원문과 위치를 확인할 수 있습니다. 금액과 성명은 잘 읽혔다는 이유만으로 최종 확정하지 않으며, 다른 서류 및 사건 정보와 대조하는 절차를 거칩니다.

## 불명확한 글자의 재확인

흐리거나 방향을 잘못 읽은 줄, 넓은 영역에 비해 비정상적으로 짧게 읽힌 줄, 숫자와 알파벳이 혼동되는 식별자는 원본 이미지로 제한된 횟수만 다시 읽습니다. 처음 읽은 내용과 다시 읽은 내용도 함께 남깁니다.

예를 들어 계좌 식별자의 숫자 0과 영문 O를 서로 다르게 읽었다면 기대하는 정답을 넣어 고치지 않습니다. 더 나은 판독이 분명한 경우에만 채택하고, 여전히 충돌하는 내용은 확인이 필요한 상태로 둡니다. 낮은 신뢰도의 줄은 자동 추출 근거에서 제외하되 원문과 대안 판독은 보존합니다.

작업 시간이 초과되거나 처리 가능한 쪽 수를 넘겨도 이미 처리한 페이지는 남깁니다. 나머지는 “시간 초과”, “처리 범위 초과”, “판독 불가” 등의 이유와 함께 검토 대상으로 표시합니다. 읽지 못한 금액이나 문장을 추측해 완성하지 않습니다.

## 판독 결과가 문서 작성으로 이어지는 방식

글자를 읽은 뒤에는 금액의 항목·기간·단위를 확인합니다. 연간 총급여를 월 실수령액으로 쓰거나, 자산 잔액을 생활비로 바꾸면 글자가 정확해도 잘못된 문서가 됩니다.

진술 문장도 같은 기준으로 검토합니다. 인용에 같은 숫자가 있다는 것만 확인하지 않고 소득·공제·재산·생활비 중 무엇을 뜻하는지, 월간인지 연간인지 함께 대조합니다. 실제 가상사례의 작성 시험에서 자산 240만원을 생활비 240만원으로 바꾼 문장은 검토에서 차단했습니다.

서류 전체를 읽지 못했거나 추출값의 원문 대조가 시간초과로 일부만 끝났다면 완료로 표시하지 않습니다. 계산과 새 초안 작성도 기다리며, 이미 읽은 내용과 기존 작성본은 보존합니다. **사건 개요 → 진행단계 → 다시 확인**에서 재검증을 요청할 수 있습니다. 같은 자료의 중복 실행과 재시도 횟수에는 제한이 있습니다.

원문 전체 대조를 마쳤지만 의미가 불명확한 항목은 보완 사유를 남깁니다. 원문과 단위·집계 근거가 확인된 사실을 1차 검토용 초안에 담을 때도 미확정 항목을 AI 검토 통과나 최종 제출 승인으로 표시하지 않습니다. 이후 흐름은 [문서 작성과 담당자 검토](document-workflow.md)에 설명되어 있습니다.

## 실제로 확인한 결과

2026년 10월 4일 기준으로 원본 파일을 직접 처리한 가상자료 시험 결과입니다. 정답 목록은 판독기에 전달하지 않았으며, 아래 수치는 서로 다른 검사 범위를 나타냅니다.

| 검사 | 확인 결과 | 남아 있는 범위 |
| --- | --- | --- |
| 기존 보관 자료 13건의 원본 대조 | 원본 파일 13건의 변경 여부 확인, 문자 PDF 12건의 저장 본문 일치, 급여 스캔 주요 8개 항목 일치 | 전체 문서의 모든 의미를 검증한 결과는 아님 |
| 첫 15종 자료와 이전 사례의 급여 스캔 3쪽 | 지정한 83개 항목 중 80개 일치, 약 12.56초 | 이전 급여 스캔 3쪽의 계좌 식별자에서 0/O 판독 충돌을 검토 대상으로 유지 |
| 별도의 두 번째 자료 15종·16쪽 | 지정한 69개 항목 모두 일치, 약 3.90초 | 문자 PDF 15쪽과 스캔 1쪽으로 구성된 고정 자료 |
| 추출·작성 후속 대조 | 두 자료에서 확인한 항목 119개·123개를 각 7종 PDF의 원문 근거에 연결 | 일반 판독 정확도, 법률 검토 또는 법원 인가를 입증하는 지표가 아님 |

시험 시간은 해당 로컬 환경에서 측정한 값입니다. 흐림·구김·필기·여러 기관의 실제 서식 전반에 대한 정확도나 처리 시간을 보장하지 않습니다. 문자 판독, 항목 해석, 문장 의미 검토, 법률 판단은 각각 확인해야 합니다.

로컬 검사 기록: 보관 원문 대조: `reports/ocr-audit/stored-original-comparison.json`, 첫 자료 판독 결과: `reports/ocr-audit/field-benchmark-final.json`, 두 번째 자료 판독 결과: `reports/ocr-audit/retest-benchmark-final.json`, 잘못된 금액 의미의 차단 기록: `reports/ocr-audit/narrative-semantic-regression.json`.

## 운영 참고

최초 설치 시 `python scripts/setup_ocr.py`를 실행합니다. 필요한 판독 파일은 설치 단계에 준비하며 고객 서류 처리 중에는 내려받지 않습니다. 기존 배포 환경에 의존성이 준비되어 있으면 `--skip-install` 옵션을 사용할 수 있습니다. 준비한 `.local/ocr` 폴더는 배포 환경에서도 유지해야 합니다.

기본 제한은 파일 10MB, PDF 100쪽, 스캔 판독 대상 20쪽, 판독 작업 180초입니다. 별도 작업으로 실행하며 시간 제한이 지나면 종료합니다. 운영자는 `DEBTOFF_OCR_MAX_PAGES`, `DEBTOFF_OCR_TIMEOUT`, `DEBTOFF_OCR_DPI` 설정을 조정할 수 있고 안전한 상한은 프로그램에서 제한합니다.

재검증은 `python -m unittest tests.test_ocr`와 [전체 항목 비교 도구](../scripts/benchmark_ocr_fields.py)로 실행합니다. 설치 출처와 파일의 변경 여부를 확인하려면 [설치 도구](../scripts/setup_ocr.py), [판독 도구의 공식 저장소](https://github.com/RapidAI/RapidOCR), [공식 배포 파일 목록](https://github.com/RapidAI/RapidOCR/blob/main/python/rapidocr/default_models.yaml)을 참고합니다.
