# 고객 포털과 안내

고객 안내와 공개 후기는 인증 없는 읽기 API로 제공하고, 내 사건·서류·알림·상담은 기존 인증과 사건 소유권 검사를 사용한다. 담당자 화면의 쟁점·고객 원문·내부 검토 결과를 공개 안내에 포함하지 않는다.

새 로컬 프로필은 사건 0건에서 시작한다. 고객 `customer/customer`, 직원 `staff/staff`, 변호사 `lawyer/lawyer` 계정은 DB에 비밀번호 해시로 저장한다. 고객은 **내 사건 → 상담·신청 시작**에서 직접 접수한다. 동의와 중복 방지 키를 검사하고 본인 고객·담당 직원·변호사와 수임번호를 연결한다. 신청만으로 분석·서류 요청을 시작하지 않는다. 담당자가 **세부 상담 요청**을 보내고 실제 상담 기록을 저장한 뒤 추출과 기존 자동 처리를 시작한다. [처음부터 테스트하기](testing.md)에 가상자료와 절차를 정리했다.

신청 본문은 `intake.application_notes`, 세부 상담은 `consultation`에 분리한다. `intake.status`는 `received` → `consultation_requested` → `completed` 순서이며 완료 이후 기록 수정도 가능하다. 대기 중에는 고객 회신·업로드·수동 분석 재시도로 추출을 우회할 수 없다. 직원이 이미 진행한 상담 회의록을 직접 등록하는 기존 경로는 유지한다.

기존 고객 신청에 상세 상담 이력이 없으면 서버 시작 시 상담 접수 상태로 전환한다. 이전 기록과 제출 원본은 보존하고, 미제출 자동 요청만 철회한다. 수동 요청·법원 개별 명령은 유지한다. 고객 화면에는 실제 수임번호만 표시하며, 수임번호가 없으면 상담 단계로 안내한다. 내부 사건 ID는 API 연결에만 사용한다.

## 화면과 경로

고객 포털은 `http://localhost:5173`에서 열린다. 화면은 `apps/frontend/src/PortalExperience.jsx`, 전용 스타일은 `apps/portal/experience.css`로 관리한다.

| 주소의 쿼리 | 메뉴 | 접근 |
| --- | --- | --- |
| `?page=home` | 메인 | 공개, 기본 진입 |
| `?page=guide` | 개인회생이란 | 공개 제도·준비 안내 |
| `?page=case` | 내 사건 | 로그인 전에는 안내, 로그인 후 본인 사건 |
| `?page=faq` | Q&A | 공개 검색·분류·공식 근거 |
| `?page=reviews` | 고객 후기 | 공개 목록, 작성은 본인 고객 계정 |

내 사건은 `tab=home`, `documents`, `messages`로 기존 진행·제출·담당자 문의 기능을 유지한다. 로그인 전에는 사건 목록을 조회하지 않는다. 우상단 로그인/계정과 알림은 모든 페이지에서 접근하며, 알림에는 고객 공개 알림만 표시한다. 확인함 처리는 기존 알림 읽음 API를 사용한다.

고정 상담창은 모든 페이지에서 열 수 있다. 비로그인 질문은 이미 받은 공개 FAQ를 화면에서 검색하고, 로그인 후 본인 사건 질문은 아래 상담 API로 연결한다. 사진은 기존 로컬 이미지와 출처 표기를 사용한다. 페이지 전환·버튼에 가벼운 움직임을 적용하고 동작 줄이기 설정을 존중한다.

## 공통 API

| 경로 | 범위 |
| --- | --- |
| `GET /api/portal/public` | 개인회생 소개·자주 묻는 질문·공식 근거·공개 후기 |
| `POST /api/portal/applications` | 고객 본인 신청·명시적 동의·같은 접수의 중복 방지·담당 배정 |
| `POST /api/cases/{id}/consultation/request` | 배정 직원·변호사의 세부 상담 요청, 고객 대화·알림 연결 |
| `POST /api/cases/{id}/consultation` | 세부 상담 내용·동의 저장, 최초 요청 확인 후 추출 시작 |
| `GET /api/portal/testing-application` | fresh 로컬 고객 전용 가상 상담 내용; 입력 채우기만 수행 |
| `GET /api/portal/testing-materials` | fresh 로컬 고객 전용 가상 서류 ZIP |
| `GET /api/notifications` | 본인 권한에 속하는 사건의 알림·미확인 개수 |
| `GET /api/portal/reviews` | 게시 중인 동의 후기 |
| `GET /api/portal/reviews/mine` | 로그인 고객이 작성한 공개/숨김 후기; 다른 작성자와 분리 |
| `POST /api/portal/reviews` | 로그인 고객의 본인 실제 사건 후기·명시적 공개 동의 |
| `DELETE /api/portal/reviews/{id}` | 작성자 동의 철회·후기 내용 삭제 또는 권한 있는 담당자 삭제 |
| `GET /api/portal/reviews/manage` | 직원에게 배정된 사건의 후기 관리 |
| `PATCH /api/portal/reviews/{id}` | 담당 직원의 숨김/게시와 사유 기록 |
| `POST /api/portal/chat` | 로그인 고객의 본인 사건에 대한 안내 연결 |
| `POST /api/portal/handoff` | 고객이 확인하고 누른 내용만 본인 사건 메시지·직원 인앱 알림으로 전달 |

`portal_routes.py`는 기존 인증·사건 권한과 변경 버전을 재사용하고 `portal_service.py`가 안내·후기·상담 연결을 담당한다. 데이터베이스에는 `portal_reviews`, 호출 한도용 `portal_chat_usage`를 추가한다.

## 안내와 상담

`data/client_guide.json`에 쉬운 설명·FAQ·공식 근거 URL·검토일을 관리한다. 신청 준비→서류 보완→변제계획→법원 심사→인가 후 이행/면책을 구분하며, 문서 작성 완료가 법원 인가를 의미하지 않는다고 안내한다. 현재 시행일과 법령 감시 상태는 안내 문구의 검토일과 별도로 확인한다.

상담창의 로컬 모델은 질문에 맞는 등록 FAQ·현재 요청 ID를 선택한다. 자유롭게 개인 법률 의견을 만들어 답하지 않는다. 서버가 허용된 항목만 검증해 안내와 출처를 반환하고, 모델 사용 불가·근거 부족이면 `reference_only` 상태로 기본 안내를 보여주며 담당자 연결을 제공한다. 원문 질문은 외부 추론 API로 보내지 않고 채팅 원문을 별도 DB에 저장하지 않는다. 호출 한도 메타데이터만 보관한다.

직원 연결은 고객이 보낼 내용을 확인하고 선택한 경우에만 실행한다. 직원 인앱 알림과 기존 사건 메시지에 남으며 문자·이메일·외부 메신저 발송 기능은 아니다.

새 신청·고객 제출·고객/직원 메시지·서류 보완·검토 알림은 종류·제목·설명과 사건 이동을 제공한다. 읽음 상태는 계정마다 저장한다. 같은 직원용 알림을 직원이 확인해도 변호사의 미확인 상태는 유지되며 응답에는 다른 사람의 읽음 기록을 노출하지 않는다. 기존 사건별 읽음 API와 버전 충돌 검사를 사용한다.

[실제 로컬 상담 검증](../reports/portal-chat-live.json)은 합성 질문에서 `answered`·`available`, 외부 처리 없음으로 완료된 실행을 기록한다. 소요시간은 45.33초이며 이 한 번의 관측을 응답시간 보장으로 해석하지 않는다.

## 후기와 결과 표시

후기는 명시적인 공개 동의와 본인 실제 사건이 있어야 등록할 수 있다. 합성 사건 후기, 실명·주민번호·전화·계좌·URL과 인가 보장 표현을 차단하고 별칭을 마스킹한다. 작성자는 후기 화면의 ‘내가 작성한 후기’에서 내용 삭제를 확인하고 공개 동의를 철회할 수 있다. 게시에는 기존 권한·중복 검사를 적용하고 별도의 사전 승인 절차를 두지 않는다. 직원은 권한 있는 사건의 문제 후기를 숨길 수 있다.

법원 결과 배지는 원문과 결과가 검증되고 작성자가 `show_outcome`에 별도로 동의한 경우에만 표시한다. 후기는 통계상 인가 표본으로 자동 편입되지 않으며 공개 응답은 사건 ID·원문·고객 개인정보를 포함하지 않는다. 가상의 고객 후기나 성과 수치를 채워 넣지 않는다.
